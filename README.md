# MaixCAM 开发助手 —— RAG × Harness 教学项目

> **当前状态**：主分支（教学主线）已完成并可运行；**54 篇文档 / 790 KB**；166 个测试通过。
> Harness 分支与 Skill 分支待做。
>
> 一份**真实可用**的 MaixPy 开发助手，同时是一份**可跟做**的 RAG 与 Agent 教学材料。

---

## 这个项目是什么

### 初衷：2025 年打电赛，模型完全不知道 MaixCAM

**2025 年**打电赛的时候，MaixCAM 还是很新的硬件——**那个时候模型完全没有它的知识**。

后果不是"答得不够好"，而是一种很具体的失败：让模型写 MaixPy 代码，
它会给你一堆**看起来对、粘进 MaixVision 就报错**的 API——参数名对一半、
把 MaixPy 的接口和 OpenCV / 树莓派 / K210 时代的 MaixPy v1 混在一起。
而且它不会说"我不知道"，它会给你一段读起来通顺的代码。

当时的应对方式是手工的：

```
翻官方 wiki → 自己判断该看哪几页 → 把内容复制给 AI → AI 再回答
```

**那套手工流程，就是一次人工执行的 RAG。**

**把这个手工流程自动化、工程化，是我做这个项目的初衷。** 而"教学"这一部分是顺着
它长出来的：既然这条链路的每一步都能被测量，那它正好可以用来讲清楚
**RAG 与 Agent 到底该怎么设计、以及怎么评估**——这比另造一个玩具例子有说服力得多。

### 它同时是两样东西

| 身份 | 服务对象 | 成功标准 |
| --- | --- | --- |
| **真实工具** | 想用 MaixCAM 做项目的人 | 问它 MaixPy 的用法，给出的代码能跑 |
| **教学材料** | 想学 RAG / Agent 的人 | 每一步为什么这么做、不这么做会怎样，都有可复现的证据 |

## 三条分支：目标不同，工程选择就不同

这个项目不是"同一个东西的三种写法"，而是**三个不同的目标**——
工程选择由目标推导，不由口味决定。

| 分支 | 目标 | 工程上的必然选择 | 状态 |
| --- | --- | --- | --- |
| **主分支** | **教学** | **从零构建**——过程本身就是目的 | ✅ 已完成 |
| **Harness 分支** | **应用价值** | **用成熟基座（DeepSeek Harness）** | ⏳ 待做 |
| **Skill 分支** | **普及** | **最轻形态**，任何桌面 Agent 装上即用 | ⏳ 待做 |

**写错的方式恰恰是**用一种分支的标准去评判另一种——说主分支"工程不成熟"、
说 Skill"功能太弱"，都是没看懂它们各自的目标。

## 两个最值得看的结果

### 一、语料工程的杠杆（第一次消融）

评测器第一次跑就抓到一个**设计缺陷**：`signature` 类问题（"某函数的参数是什么"）
召回率 **0.000**。根因不是检索算法——是 **API 参考页当时只用来生成白名单，
没有产出可检索的 chunk**，而教程层不会系统性地写出函数签名。

修复后，同一评测集、同一配置、**只改语料这一项**：

| qtype | 修复前 | 修复后 | 变化 |
| --- | --- | --- | --- |
| **signature** | **0.000** | **0.500** | **+50 pt** |
| example | 0.250 | 0.750 | +50 pt |
| **concept** | 0.625 | **0.500** | **−12.5 pt** |
| 总体 Recall@5 | 0.556 | 0.611 | +5.5 pt |

**加语料层不是免费的**——新增的 1898 个 API chunk 抢占了 Top-5 名额，
把概念类需要的教程散文挤了出去。

**而只看总分的 +5.5 pt 完全看不出这件事。** 这就是"必须按 qtype 分组看"的实证。
详见 [事故 02](./docs/postmortem/02-有文档却召不回.md)。

### 二、链与循环的真实差别（端到端）

同一个问题：*"MaixPy 里怎么做 YOLO 物体检测？给出完整例程"*，同一份语料、同一套工具。

**链式（L1 基线）**：

> 资料中没有给出 YOLO 物体检测的完整代码，因此无法提供可直接运行的完整示例。

**agent（8 轮）**：给出完整可运行代码，并**自己校验过两次**。它的轨迹值得逐步看：

```
第1轮  search_docs("YOLO 物体检测 例程")
第2轮  search_docs("YOLOv5 YOLOv8 YOLO11 …")        ← 自己改写查询
第3轮  lookup_api("maix.nn.YOLOv5")                  ← 切到确定性工具
第4轮  search_docs("yolov5.py 例程代码 detector = nn.YOLOv5 …")
第5轮  check_api_usage(草稿代码…)                    ← 写完自检
第6轮  lookup_api("maix.nn.YOLOv5.detect")           ← 补缺失的签名
第7轮  check_api_usage(修正后代码…)                  ← 再校验一次
第8轮  final
```

**差别不在模型，也不在语料，只在有没有循环。**

而成本是真实的：18 题用了 **88 次工具调用**（平均 4.9 次/题），
其中 `check_api_usage` 被调 21 次——**agent 在主动自检**，
这是链式基线完全没有的行为。

### 三、一个诚实的负面结果

L3 消融（纯检索轴，同一评测集）：

| 配置 | Recall@K | MRR |
| --- | --- | --- |
| 只 dense | 0.611 | **0.557** |
| 只 bm25 | 0.444 | 0.335 |
| **RRF 融合** | **0.611** | **0.453** |

**融合没有提升 Recall，MRR 还夹在两者中间。** 这是个有点失望的结果，
而它正是本项目的论点本身：**不是"我用了混合检索"，而是"我测出了哪些技术活了下来"。**

## 快速开始

```bash
# 1. 依赖（Python 3.10+）
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt        # Windows
# source .venv/bin/activate && pip install -r requirements.txt   # Linux/macOS

# 2. 密钥与端点（复制后填写；.env 已被 gitignore 保护）
copy .env.example .env

# 3. 嵌入模型：本地 Ollama，零成本可离线
ollama pull bge-m3

# 4. 语料 → 索引
python -m maixrag --config configs/l2_hybrid.yaml corpus adopt   # 或 corpus fetch（需网络）
python -m maixrag --config configs/l2_hybrid.yaml corpus build
python -m maixrag --config configs/l2_hybrid.yaml index build

# 5. 终端演示 —— 看 agent 一轮一轮做决策（呈现层是个可拔的插件）
python -m maixrag demo --list                      # 看能问什么，不需要密钥
python -m maixrag demo --fake-chat "MaixCAM 的 GPIO 怎么用？"   # 完全离线
python -m maixrag demo --max-turns 10 "MaixCAM 的 GPIO 怎么用？怎么点灯？"   # 真实模型

# 6. 跑主分支的 agent（不配密钥也能跑通全流程）
python -m maixrag --config configs/l2_hybrid.yaml agent "MaixPy 里怎么做 YOLO 物体检测？" --fake-chat
python -m maixrag --config configs/l2_hybrid.yaml agent "MaixPy 里怎么做 YOLO 物体检测？" --max-turns 10

# 7. 只测检索轴（不花钱、不联网、不需要模型 key）
python -m maixrag --config configs/l2_hybrid.yaml eval --level rag --fake-chat
python scripts/inspect_eval.py          # 看每条指标覆盖了多少题

# 8. 防幻觉校验器
python scripts/check_symbols_demo.py
python scripts/regress_check_api_usage.py    # 校验器真的在检查，而不是"检查了 0 个符号"
```

> **`demo` 和 `agent` 的区别**：`agent` 是给评测与调试用的（跑完一次性打印轨迹），
> `demo` 是给人看的（实时画过程 + 启动画面）。
> 两者跑的是**同一个 agent**——`demo` 只是多挂了一个呈现插件。

**为什么嵌入用本地 Ollama**：DeepSeek 不提供 embeddings 接口（实测 404）。
本地 `bge-m3` 多语言、中文强、零成本、可离线——对教学项目最合适。

## 这个项目最特别的一点

**它记录了自己犯过的错。**

大多数教学项目展示的是打磨过的正确路径。但 RAG 与 agent 工程里最难的部分，
恰恰是**东西安静地坏掉**的时候——没有报错、没有异常、指标看起来还行。

七次真实事故，每一次都有完整的症状 → 根因 → 修复 → 回归测试：

| 事故 | 教的是哪一类判断 |
| --- | --- |
| [静默的空结果](./docs/postmortem/01-静默的空结果.md) | 安静的成功是假象 |
| [有文档却召不回](./docs/postmortem/02-有文档却召不回.md) | 文档存在 ≠ 能被召回 |
| [校验器把正确代码判成幻觉](./docs/postmortem/03-校验器把正确代码判成幻觉.md) | **假阳性比漏报更危险** |
| [被清空的统计](./docs/postmortem/04-被清空的统计.md) | 状态生命周期 |
| [伪装成好消息的 0](./docs/postmortem/05-伪装成好消息的0.md) | 指标会伪装成好消息 |
| [预算与任务不匹配](./docs/postmortem/06-预算与任务不匹配.md) | 参数要匹配任务 |
| [校验静默放行](./docs/postmortem/07-校验静默放行.md) | **"没查出错" ≠ "没查"** |

**七条覆盖七种不同类别的判断力**，而每一条都能被复现。

> 第七条是**跑终端演示时发现的**：agent 在答案最后自己写道
> 「这次自检实际没有起到校验作用」。顺这句话查下去，发现第一级防幻觉校验
> 在最需要它的那条路径上一次也没生效，却对模型返回了成功。
> 有些 bug 不是难修，是**难被看见**——这就是演示程序的额外价值。

## 三个可以立刻跑的演示

不用配任何东西，`git clone` 之后就能跑。它们对应教学设计里的三个**故意写错**，
分别埋在三类不同性质的错误上：

```bash
python scripts/demo_planes.py     # 架构错：把服务放错平面
python scripts/demo_budget.py     # 工程错：不设预算的 agent 会跑飞（且失败是无声的）
python scripts/demo_sandbox.py    # 安全错：权限越界，"拦住了"≠"拦对了"
```

另外还有一个**给人看的**终端演示（启动画面 + 实时轨迹 + 可插拔呈现层）：

```bash
python -m maixrag demo --fake-chat "MaixCAM 的 GPIO 怎么用？"
```

它的呈现层是一个**插件**，不是硬编码进循环的。把它拔掉，agent 一行代码都不用改。
"可插拔"这个说法唯一的证明方式，就是真的插拔一次——见
[tutorial 08 终端演示](./docs/tutorial/08-终端演示.md)。

## 语料底数（实测，2026-08）

| 分区 | 页数 | 字节数（实测） |
| --- | --- | --- |
| `docs/doc/zh` 中文教程 | 130 | 713,520 |
| `docs/doc/en` 英文教程 | 129 | 733,937 |
| API 参考（文档站） | 57 条 | 未测 |

- 教程有 **Markdown 原文**可直接获取（仓库 `docs/doc/zh`，**Apache-2.0**），无需爬 HTML；
- API 参考由源码 docstring 生成，**不在仓库 Markdown 里**，需从文档站抓取或自行构建；
- 文档站提供 `sitemap.xml`，语料边界可程序精确枚举；
- 站点与仓库存在**页面漂移**，管线会显式产出差异报告而非静默丢弃。

**这个体量决定了第一课**：实测中文教程 713,520 字节、token 估算 **20 万以上**——
**单独就超出了"全文塞进 prompt"的可行区间**（该经验阈值约 20 万 token，来源为
厂商工程博客，属 `[厂商自测]`）。但单个模块（如 `peripheral`，约 2 万 token）全塞绰绰有余。

**所以第一课问的不是"该不该用 RAG"，而是一条边界曲线**：覆盖面多大时全文上下文开始不划算。

## 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python | RAG 教学生态最主流，新手最容易跑起来 |
| 模型接入 | **OpenAI 兼容接口** | 一套配置接任意提供方 |
| 编排 | **自写，不用 LangChain / LlamaIndex** | 要精确控制每一层才能做消融；透明的实现更有教学价值 |
| 检索 | NumPy 暴力检索 + 手写 BM25 | 语料小（数千 chunk），暴力检索毫秒级，且完全可读 |
| 向量库 | 落盘矩阵，不引外部数据库 | 单机、零运维 |
| 分词 | jieba + 中文标识符保留 | 通用中文分词会把 `maix.image.Image` 切碎，直接损失最重要的一类查询信号 |
