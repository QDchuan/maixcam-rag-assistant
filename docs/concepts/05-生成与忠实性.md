# 05 · 生成与忠实性

> **这一章要建立的认知**：生成不是"把片段喂给模型让它写"。
> 它的真正任务是在**只有一个说话权**的前提下，保证每句话都能被程序追溯到证据，
> 并且保留说"我不知道"的权利。
>
> 相关：[tutorial 00 主线导览](../tutorial/00-主线导览.md) ·
> [事故 05 伪装成好消息的 0](../postmortem/05-伪装成好消息的0.md) ·
> 习题：[`exercises/concepts/05-生成与忠实性.md`](../exercises/concepts/05-生成与忠实性.md)

## 1. 一句话

**生成层的任务不是"答得像"，而是"答得可追溯"**——
每一句论断指向一个可核对的证据编号，每一段代码里的符号都能在语料里找到出处，
找不到的时候就明确说找不到。

## 2. 它在链路中的位置

```
用户问题
   ↓
[检索] → [融合] → [重排序]
   ↓
┌───────────────────────────────────────────────┐
│  生成层                                        │  ← 本章
│   ├─ 上下文按 [1][2][3] 编号给出               │
│   ├─ 模型要求返回 JSON：                       │
│   │    answer / citations / unsupported        │
│   ├─ 校验阶梯：AST+符号 → 签名 → 真实执行      │
│   └─ 拒答是一等输出（refused 字段）             │
└───────────────────────────────────────────────┘
   ↓
Answer(text, citations, refused, verification)
   ↓
[CLI / 服务 / agent 循环消费这个结构]
```

**输入**：带编号的上下文块（每条含来源、章节、类型、正文）+ 用户问题
**输出**：一个 `Answer` 对象——`text`、结构化 `citations`、`refused`、
校验结果 `verification`（数据模型见 `maixrag/models.py`）
**下游要它做什么**：**要能拿出证据，而不只是给出文字。**
前面所有环节的努力到这一层才第一次面向用户：检索失败只是"少答一点"，
生成层的失败是**直接对用户说假话**。**校验阶梯长在这里的原因就是这个。**

## 3. 为什么需要它（没有它会怎样）

从真实的失败讲起，不讲定义。

**MaixCAM 是比较新的硬件，大模型训练语料里几乎没有它。** 让它写 MaixPy 代码，
它会给出参数名对一半、把 MaixPy 接口和 OpenCV / 树莓派混在一起的 API。
这些代码**看起来是对的**，粘进 IDE 才报错。

RAG 本来应该解决这件事：把官方文档喂进上下文。但它只解决了**一半**：
检索负责"资料有没有进上下文"，生成负责"模型有没有用上下文说话"。
**这两件事可以独立地坏。** 本项目测到过一次两条轴各坏一边的结果，
就是 `MaixPy 里怎么做 YOLO 物体检测？给出完整代码` 这道题：

| 轴 | 表现 | 结论 |
| --- | --- | --- |
| 生成轴 | **优秀**——模型不编造 API、明确拒答、引用规范 | 提示词纪律生效 |
| 检索轴 | **失败**——真正含 YOLO 例程的 `zh/vision/yolov5` 没被召回 | 根因在这里 |

**如果只看"答案里没有代码"就去调提示词、换模型，那就全部调错方向了。**

## 4. 本项目的实测证据

### 4.1 两条轴的生成侧数字 [本项目实测]

同一批 18 题、同一份语料：

| 指标 | 链式（L1） | agent 循环 |
| --- | --- | --- |
| 引用精确率 | 0.889 | 0.833 |
| 引用召回率 | 0.889 | 0.833 |
| 符号级幻觉率 | 0.000（**但覆盖面 0/18**） | **0.000** |
| 拒答率 | 0.000 | **0.500** |

**agent 的拒答率是 0.500**——它有一半的题没有给出正面回答。
这不全是"学会了诚实"：循环的终止原因是 `budget` / `stuck` / `error` 时，
下游就把这次运行记为拒答（`maixrag/agent/app.py` 的 `_looks_like_refusal`）。
所以这个 0.500 里混着**真实的"资料不足"**和**"预算用完没做完"**——把它们分开，
是这一章留下的一个具体问题。

这是本章最重要的一张表，因为它把两件事摆在同一行：
**幻觉率 0.000 和拒答率 0.500 必须一起读。** 只说前者是把权衡藏起来。

### 4.2 幻觉率 0.000 的两种含义 [本项目实测]

同一个 0.000，本项目见到过两种：

- 链式那一栏的 0.000，诊断脚本打出的覆盖率是 **符号被检查到的题数 0/18**——
  模型没有拿到 API 资料，按纪律不写代码，于是**没有符号可检查**。这个 0 是"没测到"。
- 修掉检索问题之后，覆盖率到了 **18/18**，幻觉率仍是 0.000——**这一次它是真的**。

**区别不在数字，在覆盖面。** 详见 [事故 05](../postmortem/05-伪装成好消息的0.md)。

### 4.3 agent 的自检行为 [本项目实测]

18 题一共 88 次工具调用（平均 4.9 次/题）：

```
search_docs       31
lookup_api        25
check_api_usage   21
list_api          11
```

`check_api_usage` 被调了 **21 次**：agent 在**写完代码之后主动校验**，
链式基线完全没有这个行为。这 21 次自检是幻觉率能保持 0.000 的直接原因，
也是循环最实在的一项收益——**不是"答得更聪明"，是"知道自己可能错并去查"**。

### 4.4 本项目的设计选择 [设计判断]

以下四条**没有实测数字支撑**，是设计决策，依据写在
[01 系统架构设计 · 4.5 生成层](../design/01-系统架构设计.md)：

1. **编号是引用机制的载体。** 上下文以 `[1][2]` 结构化块给出，模型被要求用 `[1]` 标注依据，
   引用因而是**程序可校验的**，不靠事后字符串匹配。
2. **`unsupported` 是给模型的正式出口。** 结构化输出里留一个字段专门装"这部分资料未覆盖"——
   模型编造常常是因为没有被提供一个体面的方式说"我不知道"。
3. **拒答是一等输出。** `Answer.refused` 是显式字段，不靠文本里有没有"我不知道"去猜；
   检索为空时直接拒答（`RagProfile.answer`），并仍然返回相关片段。
4. **三级校验阶梯**：AST + 符号存在性（零成本、纯本地、抓主要幻觉）→ 签名与参数校验 →
   真实执行（真机或 mock shim）。原则是**能用程序判的绝不交给模型，能在本地判的绝不上设备**。
   三级的失败处理逐级放宽：第一级阻断，第二级警告并标注，第三级只记录。

> **一个诚实的实现现状**（三处缺口，都是本章自己暴露出来的）：
> `unsupported` 被解析出来（`maixrag/builders.py`）但**还没有被下游消费**；
> 配置里的 `refuse_threshold` 已声明、**还没有被实现使用**；
> agent 那条路的 `citations` 是**从答案文本里的 `[n]` 反向抽取**的
> （`maixrag/agent/app.py`），而不是让模型结构化返回——抽取的输入和校验的输入同源，
> 会削弱这道检查的独立性。
>
> **一个没人读的出口不算出口。** 这三条是明确待补的工程缺口，不是设计意图。

## 5. 关键术语

| 术语 | 一句话 |
| --- | --- |
| **忠实性（faithfulness）** | 答案里的论断有多少能被给定上下文支撑 |
| **引用编号** | 上下文块的 `[1]` 标号，让"这句话的依据在哪"可被核对 |
| **结构化引用（`citations`）** | 引用以字段返回而非正文里的字符串，所以能被程序校验 |
| **`unsupported`** | 模型显式声明"资料未覆盖"的字段——承认无知的正式出口 |
| **拒答（refusal）** | 一种正常输出，不是异常；对应 `Answer.refused` |
| **符号（symbol）** | 代码里 `maix.*` 形态的限定名，防幻觉校验的检查单位 |
| **符号白名单（API roster）** | 1898 个符号 / 4868 条，符号存在性校验的物理依据 |
| **幻觉率（符号级）** | 代码块中不在白名单里的符号占比——完全程序可判 |
| **覆盖面** | 这条指标实际检查了多少题；没有它，比率型指标会伪装成好消息 |
| **三级校验阶梯** | 存在性 → 签名/参数 → 真实执行，从最便宜最确定的开始 |

## 6. 常见误解

这一节是这一章最重要的部分——**建立认知主要靠纠正错误认知**。

### 误解一："提示词里写'不要编造'就够了"

**错在哪**：提示词是**劝告**，不是**机制**。它没有强制力，也无法被验证。

这个错法很常见，因为成本最低——改一行字符串，看起来问题解决了；
而且它**在简单样例上经常真的有效**，给人一种"已经防住了"的错觉。

本项目的做法是把同一件事做两遍：提示词里写"代码里的每个符号都必须来自资料"
（`maixrag/builders.py` 的 `SYSTEM_PROMPT`），**同时**用白名单程序校验一遍。
前者降低发生率，后者**让漏网的一定被看见**。

> **符号白名单是防幻觉的物理基础**：没有工程化好的 API 语料，
> "代码里不许出现不存在的符号"就只能靠模型自觉。

### 误解二："幻觉率越低越好、拒答越少越好"

**错在哪**：这两个目标在同一个旋钮上，**只能一起读**。

幻觉率的分子是"编造的符号"，拒答率的分子是"没答的题"。把系统调到极端保守，
两个数字会朝相反方向走——而**只看其中一个，任何一端都能造出一个漂亮数字**。

这个错法常见，因为报表天然是一列一列的，而人一次只盯一个数。

本项目见过这条误解的极端形态：幻觉率 **0.000**，看起来很完美，
实际是**模型根本没写代码**（覆盖率 0/18）。所以正确的读法是
**"幻觉率 0.000（检查了 18/18 题），拒答率 0.500"**——带分母、带配对指标。

### 误解三："引用对不对是语义问题，得用模型来判"

**错在哪**：引用有效性**不需要语义理解**。检查 `[n]` 是否指向真实存在的上下文块、
答案里的每个 `[n]` 是否都在结构化 `citations` 里——这是几行正则加集合运算的事。

这个错法常见，是因为"判断引用质量"听起来很深奥，而引入一个 judge 模型看起来很专业。
代价是：judge 有成本、有延迟、有偏差，**而且它的正确性本身还要再被验证一次**。

本项目的纪律是：**能程序判的指标，一个都不要交给 LLM 判。**
去读 `maixrag/evaluation/harness.py` 里 `citation_precision` / `citation_recall` 的实现——
完全确定，零成本。只有 `Faithfulness` 这类才需要模型判断。

### 误解四："拒答是失败，是兜底的异常路径"

**错在哪**：拒答是**一等输出**，有自己的字段、自己的原因、自己的评测指标。

把它当异常会带来具体的坏结果：检索为空时系统宁可让模型凭记忆硬答，
因为它"不能没有答案"。

本项目的建模刻意反过来：`refused` 是显式字段，不是靠文本里有没有"我不知道"来猜；
检索为空时**直接拒答，不调用模型**。而且拒答时**仍然返回检索到的相关片段**，
说明"资料里没有直接答案，但以下是相关章节"——比一句冷冰冰的"我不知道"有用得多。

> 注意别把这条读成"拒答越多越好"。拒答是能力，**拒在哪儿**才是质量——
> 所以评测里区分 `refusal_rate`（拒了多少）与 `refusal_correct`（拒得对不对）。

### 误解五："白名单建好一次就够，抓不住就是模型在编"

**错在哪**：白名单本身会错，而且它的错误会**摧毁整个校验机制**。

本项目踩过一次：校验器把**正确的** `gpio.GPIO`、`gpio.Mode.OUT` 判成幻觉。
根因是 API 文档的模块路径（`maix.peripheral.gpio`）≠ 用户实际 import 的路径
（`from maix import gpio` → `maix.gpio`）。白名单只收了文档路径形式，
于是正确代码被系统性误报。白名单因此从 2996 条修到 4833 条，再补到 4868 条——
详见 [事故 03](../postmortem/03-校验器把正确代码判成幻觉.md)。

这个错法常见，因为**"模型在编"是一个太顺手的解释**：报告说幻觉，模型是概率系统，
归因看起来很自然。但一个误报的校验器比没有校验器更糟——
它会训练使用者忽略警告，于是真幻觉也一起被忽略。

## 7. 这一章留下的问题

读到这里，你应该能回答下面这些问题。**答不出来说明前面没读透。**

答案在 [`exercises/answers/05-生成与忠实性.md`](../exercises/answers/05-生成与忠实性.md)。

1. 上下文块为什么必须带编号，而不是把片段直接拼成一段文本？
   编号让哪些事情从"靠事后字符串匹配"变成"可程序校验"？
2. 幻觉率 0.000 在什么条件下是"真的很好"，在什么条件下是"几乎没测到东西"？
   报告里必须同时出现哪个数字才能区分这两种情况？
3. 只报"幻觉率 0.000"和同时报"拒答率 0.500"，会让技术决策差在哪一步？
4. 三级校验阶梯为什么从"最便宜最确定的一级"开始，而不是从"最有说服力的一级"开始？
   如果你只有一个真机环境、没有 shim，你会怎么安排这三级的顺序，代价是什么？

**动手题**（见 [tutorial 00 主线导览](../tutorial/00-主线导览.md) 第 5 节）：
跑 `python scripts/check_symbols_demo.py`，看校验器放行了哪些、抓到了哪些；
再跑一次评测加 `python scripts/inspect_eval.py`，看每条指标实际覆盖了多少题。

## 8. 一句话总结

> **生成的产物不是一个字符串，而是一份"带证据的声明"。**
> 它的质量由三个数共同定义——**幻觉率、拒答率、覆盖面**——
> 少报任何一个，另外两个都能被用来骗人。
