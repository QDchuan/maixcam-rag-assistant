# 00 · 为什么需要 RAG

> **这一章要建立的认知**：RAG 不是"让模型更聪明"，而是**在回答的那一刻，把权威文档
> 送到模型眼前**。它解决的不是能力问题，是**知识的存放位置问题**。
>
> 相关：[tutorial 00 主线导览](../tutorial/00-主线导览.md)·
> [事故 02 有文档却召不回](../postmortem/02-有文档却召不回.md) ·
> 习题：[`exercises/concepts/00-为什么需要RAG.md`](../exercises/concepts/00-为什么需要RAG.md)

## 1. 一句话

**模型写不好 MaixPy 代码，不是因为它笨，而是因为 MaixPy 的知识只存在于官方文档里——
而模型在训练时没见过那些文档。**

RAG 的全部动作就是一句话：**回答之前，先把相关的官方文档找出来，塞进它的上下文。**

## 2. 它在链路中的位置

```
你的问题（"MaixPy 里怎么找色块？"）
   ↓
┌──────────────────────────────────────┐
│  检索（本章）                          │
│   从 3838 个 chunk 里选出几个          │
│   ↓                                  │
│  拼进提示词："依据以下资料回答……"      │  ← RAG 这两个字指的就是这一步
└──────────────────────────────────────┘
   ↓
[生成] → 答案 + 引用 → [符号校验] → [拒答 / 交付]
```

**输入**：一个用自然语言提出的问题。
**输出**：若干条带出处（`doc_id` / URL）的文档片段。
**下游要它做什么**：把片段放进模型的上下文，让模型**照着资料写**，而不是**照着记忆写**。

> **最后一条是理解本章的钥匙**：因为下游要的是"可核对的依据"，所以检索层交付的
> 必须是**片段加出处**，而不是"一个答案"。检索层一旦开始替模型下结论，
> 后面的引用校验与拒答机制就全部失效了。

## 3. 为什么需要它（没有它会怎样）

### 3.1 先看失败长什么样

让一个通用大模型写 MaixPy 代码，你会拿到**读起来通顺、粘进 MaixVision 就报错**的东西：

| 真实问题 | 模型的典型反应 | 它错在哪 |
| --- | --- | --- |
| "MaixCAM 上怎么用摄像头拍图" | 写出 `cv2.VideoCapture(0)` 或 `PiCamera()` | 把 OpenCV、树莓派的习惯带进来了 |
| "Camera 怎么读一帧" | 写出 `cam.read_frame()` | 真名是 `read(block, block_ms)` |
| "怎么找色块" | 写出 `cv2.findContours` + `cv2.inRange` | MaixPy 用的是 `img.find_blobs(thresholds, ...)` |
| "GPIO 怎么点灯" | 写出 `RPi.GPIO` / `wiringpi` | 真名是 `gpio.GPIO` + `pinmap.set_pin_function` |
| "怎么转灰度" | 写出 `cv2.cvtColor` | 与 MaixPy 的 image 接口混在了一起 |

这些不是编出来的例子——它们就是本项目的评测集里 `must_not_contain` 字段**实际禁掉的东西**
（`eval/datasets/seed.jsonl`）。也就是说：**每一条禁项背后都对应一次真实发生过的错。**

除了"混进别的生态"，还有更讨厌的一类：**把 K210 时代 MaixPy v1 的习惯带进来**。
MaixCam 上的 MaixPy v4 是重写过的（[`corpus/raw/repo/faq.md`](../../corpus/raw/repo/faq.md) 里官方
自己说 v4 是"吸取 v1/v3 经验"的另一套东西），但 v1 的文档在网上流传得更久、更广，
所以模型更可能"记得"那套已经不适用的写法。

### 3.2 关键判断：这不是"模型笨"，是"知识没放在模型能拿到的地方"

本项目的立场很明确：

> **缺失的知识只有官方文档里有，而模型没见过官方文档。**

这个判断能推出三个立得住的结论：

1. **换更大的模型不能保证解决。** 参数量不改变一件事：那批文档在预训练语料里几乎是缺席的。
2. **提示词里反复叮嘱"不要编造 API"也不能解决。** 模型没有"不知道就一定能停下"的能力——
   它是在**续写**，不是**查表**。不给资料，它只能继续用最像的旧习惯补上。
3. **正确做法是把资料给它。** 这就是 RAG：不改变模型，改变**模型此刻能看到什么**。

### 3.3 这套流程其实你早就手工跑过

本项目起源于**2025 年打电赛时的一次真实经历**——那时候 MaixCAM 还很新，
**模型完全没有它的知识**，写出来的 MaixPy 代码基本不能用。当时遇到问题的实际动作是：

```
遇到报错 → 翻 wiki.sipeed.com → 自己判断该看哪几页
        → 把内容复制进对话框 → AI 给建议 / 写代码 → 不行再回去翻
```

**把这段流程横过来看，它就是一条 RAG 链路**：

| 手工动作 | 对应的系统环节 |
| --- | --- |
| 翻 wiki、自己判断看哪几页 | **检索**（而且是最容易出错的一环） |
| 复制内容进对话框 | **上下文注入 / 提示词装配** |
| AI 给建议 | **生成** |
| "不行再回去翻" | **反馈与拒绝** |

人工版本的问题不在于方向错了，而在于它**不稳定、不可复现、不可测量**：
出了问题说不清是"没找对页"还是"模型没用好"。本项目要做的，就是把这条链路自动化，
并**把每一步的质量变成可测量的**（见 [07 评测 · 两条轴](./07-评测-两条轴.md)）。

## 4. 本项目的实测证据

本章的"为什么"不是推演，有四组真实数据支撑。

**证据一：幻觉有具体的形状，可以被列成清单。**
`eval/datasets/seed.jsonl` 的 18 道题里，16 道带 `must_not_contain` 禁项，
其中 13 道禁掉的是**别的生态的 API**（`cv2.VideoCapture`、`cv2.findContours`、`RPi.GPIO`、
`pyaudio`、`torchvision.models`、`serial.Serial`、`nmcli`、`ffmpeg -f v4l2` ……）。[本项目实测]
说明要防的幻觉不是随机噪声，而是有规律的"串味"。

**证据二：没有资料时，模型的纪律反应是拒答。**
L1 链式基线在 YOLO 那道题上明确说"资料中没有给出完整代码……不能凭其他框架
（OpenCV、K210 时代 MaixPy v1）的习惯推测 API"，同一批测试的**符号级幻觉率 0.000**。
[本项目实测，见 [05 伪装成好消息的 0](../postmortem/05-伪装成好消息的0.md)]
但这个 0.000 起初是**假的好消息**——它其实是因为"模型压根没写代码"（覆盖率 0/18）；
修好检索后覆盖率变成 16/18，同样的 0.000 才是真的。

**证据三：把它做成循环之后，能力被"解锁"了。**
同一个 YOLO 问题，agent 版给了完整可运行代码，靠自己改写查询、切到 `lookup_api`、
再用 `check_api_usage` 自检两次拿到结果。18 道题共用 **75 次工具调用**（平均 4.2 次/题）。[本项目实测]
**差别不在模型、不在语料，只在"它有没有机会去把资料找回来"。**

**证据四：符号白名单是防幻觉的物理基础。**
项目从 API 参考页抽出 **1898 个符号 / 4868 条**白名单（`corpus/processed/api_roster.txt`），
让"代码里出现的 MaixPy 符号必须存在"从一个模糊愿望变成一次确定性的查表。[本项目实测]
没有这一步，"不编造 API"只能靠模型自觉。

## 5. 关键术语

| 术语 | 一句话 |
| --- | --- |
| **幻觉（hallucination）** | 模型给出通顺、自信，但在事实或 API 上不成立的内容 |
| **RAG** | Retrieval-Augmented Generation：生成前先检索权威资料并放进上下文 |
| **上下文（context）** | 这次请求里模型实际能读到的全部文本——它**不是**模型的记忆 |
| **chunk** | 语料被切分后的最小可检索单元（本项目共 3838 个） |
| **召回（recall）** | 该被找到的片段，有多少真的进了 Top-K |
| **ground truth** | 每道题标注的"必须被召回的那一页 / 必须出现的关键字符串" |
| **符号白名单（roster）** | 允许出现的 MaixPy API 名单；不在名单里的符号即为幻觉嫌疑 |
| **拒答** | 检索不到依据时明确说"资料里没有"，是正常输出而非异常 |

## 6. 常见误解

这一节是本章最重要的部分——**建立认知主要靠纠正错误认知**。

### 误解一："换个更强的模型就好了"

这是最普遍、也最贵的一种错。它听起来合理：效果差嘛，模型不够强。

**错在哪**：幻觉的根因是**知识缺失**，不是**推理不足**。一个更强的模型面对
"MaixPy v4 的 `read()` 参数是什么"时，处境和弱模型一样——它也只能续写最像的写法。
能力提升的是它**用好你给的资料**的水平，不是它**凭空知道资料**的水平。

**为什么这个错法很常见**：因为换模型是**一个不需要理解系统的动作**。
调提示词、改切分、建评测都要先搞懂自己在做什么；换模型只要改一行配置。
人在面对"看不见的失败"时，天然倾向于选那个最容易执行的动作。

### 误解二："RAG 就是让模型记住文档"

**错在哪**：RAG **不写入模型权重**，什么都不"记住"。文档始终存放在外部
（本项目的 3838 个 chunk 在磁盘上），每次回答时现查现给。

这个区别不是修辞，它决定了系统的全部性质：文档改了，下一次回答就是新的
（本项目为此**把语料版本固定到 commit**——不过要如实说明：这是 `corpus fetch`
会做的动作，而仓库里现在这一版 `corpus/manifest.json` 是 `corpus adopt` 从磁盘重建的，
`pinned: false`、`commit` 为空，即**尚未固定上游版本**，见
[01 系统架构设计 · 4.1](../design/01-系统架构设计.md)）；
你可以**指出答案依据的原文**；你也可以让校验器**逐个核对答案里出现的符号**。
如果知识被"记"进了权重，上面三件事都做不到。

**为什么这个错法很常见**：因为"增强"这个词容易让人联想到"训练/微调"。
而它实际增强的不是模型，是**这一次请求的上下文**。

### 误解三："有了长上下文就不需要 RAG"

这条要讲清楚**边界，而不是站队**。本项目实测过语料体积
（[00 项目定位 · 5.4](../design/00-项目定位与教学大纲.md)）：

| 覆盖面 | 估算 token | 结论 |
| --- | --- | --- |
| 单模块全文（如 `peripheral` 相关页） | 约 **2 万** | 远在阈值内，可以全塞，且**很可能优于检索** |
| 全中文教程（实测 713,520 字节） | 约 **20 万+** | **已越线** |
| 中文教程 + API 参考 | 约 **30 万** | 明显不可行 |

[本项目实测（字节数）+ 估算（token）]

所以正确的说法是：**这是边界问题，不是二元问题。**
20 万 token 这个阈值本身是厂商观点（[本项目按厂商自测引用](../design/00-项目定位与教学大纲.md)），
本项目把它当**假设**而非结论——而恰好，MaixPy 的语料就压在这条线上。

**为什么这个错法很常见**：因为"上下文窗口在变大"是真的，于是容易被推成
"检索迟早没用了"。但推错了一步：窗口变大只把边界往外挪了一点，
而语料、日志、多轮对话的增长速度远快于窗口——**边界会一直被越过去**。

> 本项目的处理方式是把"全文上下文"作为 **L-1 级**，拆成单模块 / 全中文 / 全量三档去测，
> 得到的不是"该不该用 RAG"，而是**一条"覆盖面多大时全塞开始不划算"的曲线**。

## 7. 这一章留下的问题

读到这里，你应该能回答下面这些问题。**答不出来说明前面没读透。**
参考答案：[`exercises/answers/00-为什么需要RAG.md`](../exercises/answers/00-为什么需要RAG.md)。

1. **（概念）** 为什么"模型编造 MaixPy API"这件事，**提高模型能力不是它的解法**？
   请用"知识在哪儿"这个视角回答，而不要用"模型够不够聪明"。
2. **（概念）** 本项目手工流程里的哪一步对应检索、哪一步对应生成？
   把这两步搞混会导致什么后果？
3. **（工程）** 你的语料只有 2 万 token，全塞进 prompt 和上 RAG，你会选哪个？
   说出**代价**和**失效条件**，不要只给结论。
4. **（工程）** 哪些幻觉是"把权威文档喂给模型"也救不回来的？举一类并说明理由。

**动手题**见 tutorial 00：把 `eval/datasets/seed.jsonl` 里 13 道题的 `must_not_contain`
按"串了哪个生态"分类（OpenCV / 树莓派 / K210 时代 / 其他），
再挑一条去 `corpus/raw/repo/` 里找出**官方的正确写法**。

## 8. 一句话总结

> **RAG 不改变模型，它改变模型此刻能看到什么。**
>
> 幻觉的根因是知识不在模型手里，所以解法不是让它更聪明，
> 而是在它开口之前，**把权威文档放到它眼前**——
> 至于"放多少、放哪几段"，那是后面每一章要回答的问题。
