## 一、概念问答（考框架 / 流程 / 算法 / 术语）

**Q1. 权限层有三层边界，每一层各回答什么问题？为什么检查顺序必须是能力 → 范围 → 审批，反过来会付出什么代价？**

- 提示：想清楚哪一层会"打扰人"，以及一次本来就会被拒的调用为什么不该走到那一层
- 代码现场：[`maixrag/agent/sandbox.py`](../../../maixrag/agent/sandbox.py) 的 `SandboxPolicy.check()`
> 参考答案：[answers/08-权限与沙盒.md](../answers/08-权限与沙盒.md) 第 Q1 题

**Q2. 在 MaixCAM 助手里，agent 被允许写 `<base>/workspace`。有人提交了一个路径 `<base>/workspace-evil/x.txt`，字符串前缀判断放行了它，`relative_to` 却拦住了。差别落在哪个字符上？为什么这个错特别难被发现？**

- 提示：字符串比的是什么，越界检查真正想判的又是什么
- 代码现场：[`maixrag/agent/sandbox.py`](../../../maixrag/agent/sandbox.py) 的 `path_within()`
> 参考答案：[answers/08-权限与沙盒.md](../answers/08-权限与沙盒.md) 第 Q2 题

**Q3. 什么叫"失败关闭"？在本项目的权限层里，它至少落在哪三个具体位置上？**

- 提示：先回答"这条原则防止的是哪一种默认实现"，再去找代码里对应的三个 `return`
- 代码现场：[`maixrag/agent/sandbox.py`](../../../maixrag/agent/sandbox.py)，以及 [`scripts/demo_sandbox.py`](../../../scripts/demo_sandbox.py) 场景四
> 参考答案：[answers/08-权限与沙盒.md](../answers/08-权限与沙盒.md) 第 Q3 题

**Q4（补充概念题）. 权限层为什么会成为 agent 里"最容易被略过"的一层？在同一个工具执行管线里，漏配权限与漏配参数校验，失败形态有什么不同？**

## 二、工程问答（考局限性 / 选型 / 取舍 / 边界）

**Q5. 在 MaixCAM 助手里加一个导出工具（把检测结果写到用户指定目录，如 `<base>/exports/`）。它声明了 `requires={fs:write}`，但没有声明 `path_params`：能力层放行，范围层完全不检查。你会选"约定 + 审查"，还是干脆不提供"以路径为参数"的工具形态？**

- 提示：两条路各自把风险推给了谁，代价又落在哪一环
- 依据：[`tests/test_agent_sandbox.py`](../../../tests/test_agent_sandbox.py) 的 `test_scope_check_only_applies_to_declared_path_params` · [`concepts/08`](../concepts/08-权限与沙盒.md) 第 5、6 节

**Q6. 本项目的命令白名单用字符串前缀匹配（`cmd.startswith(a)`）。给出一条能绕过它的命令形态，并说明你会把修复放在哪一层（能力 / 范围 / 审批）、为什么修在那一层。**

- 提示：白名单里放了 `ls`，那么"以 `ls` 开头"的命令实际包括哪些形态

**Q7. 你们在无人值守的批处理里跑 agent（夜间脚本，没有人能点审批弹窗）。假设有人提议把 `DenyApprovalUnavailable` 改成"没人可问就放行，等有人的时候再问"。说出这个改动会让哪些收益消失、又会露出哪些新风险，并给出你的方案。**

- 提示：这条改动的代价不是"多了一层保险还是少了一层保险"，而是审批层的存在形态变了

## 三、动手题

**H1. 亲手跑一遍 `scripts/demo_sandbox.py`，把四个场景的判定结果先写下来再对照输出；对场景三，逐行判定三种绕过方式在"字符串前缀"和"规范化 + 解析链接"两列各是什么结论，并解释为什么这一脚本在 Windows 上可能少一行。**

- 提示：场景三的第三个用例需要真的建出符号链接才有意义——不存在的路径 `resolve()` 不会解析
- 验收标准：能写出"兄弟前缀目录"与"两点向上穿越"两行在两列下的**全部四个格子**，方向与脚本输出一致；能说出符号链接那一行缺失时脚本额外打印了什么，以及这一行的结论由谁负责验证
- 依据：[`scripts/demo_sandbox.py`](../../../scripts/demo_sandbox.py) · [`concepts/08`](../concepts/08-权限与沙盒.md) 第 4 节证据二与证据五
> 参考答案：[answers/08-权限与沙盒.md](../answers/08-权限与沙盒.md) 第 H1 题

**H2. 给沙盒加一条"写操作需要审批"的策略，让一次越界写入从"直接拒绝"变成"等待审批"。先写下预测：装上有审批人的版本之后，越界写入的判定字段会怎么变；再用 `AlwaysApprove` 与默认的 `DenyApprovalUnavailable` 各跑一次对照。**

- 提示：先看 `SandboxPolicy` 的三个字段（`allowed` / `needs_approval` / `approver`）分别管哪一层；注意 `check()` 里审批判定写在范围检查之后
- 验收标准：两次对照的 `allowed` 与 `needs_approval` 组合与自己写下的预测一致；若越界写入在两种审批人下**给出同一个结果**，能说出是哪一层的判定先返回了，以及为什么这恰好是顺序设计的意图
- 依据：[tutorial 00 · §5 练习 4](../../tutorial/00-主线导览.md) · [`concepts/08`](../concepts/08-权限与沙盒.md) 第 2、7 节 · [`tests/test_agent_sandbox.py`](../../../tests/test_agent_sandbox.py) 的 `test_exec_allowlist_gates_commands`
> 参考答案：[answers/08-权限与沙盒.md](../answers/08-权限与沙盒.md) 第 H2 题
