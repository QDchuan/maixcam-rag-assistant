# 习题 · 00 为什么需要 RAG

> 对应概念文档：[concepts/00-为什么需要RAG.md](../concepts/00-为什么需要RAG.md)
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md)　← **先自己想，再看答案**

这一章的题从概念文档第 7 节「这一章留下的问题」长出来，**全部落在 MaixCAM / MaixPy 的真实场景上**。
没有填空题，也没有"请解释什么是 X"——每道题要么是"你会怎么做"，要么是"这个现象说明了什么"。
做题规则见[习题册说明](../../README.md)。

---

## 一、概念问答（考框架 / 流程 / 算法 / 术语）

**Q1. 队友说"下个月换一个更强的模型，MaixPy 老编 API 的问题就解决了"，让你评估这个决定。用"知识在哪儿"的视角说明：为什么换模型不是这个问题的解法？**

- 提示：先问一句——那批正确的写法现在存在哪里、在谁手里，预训练语料里有没有它们。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q1 题

**Q2. 电赛时那条手工流程（翻 wiki → 自己判断该看哪几页 → 复制进对话框 → AI 给建议）整体搬进系统时，哪一步对应检索、哪一步对应生成？把这两步揉成一个动作，排障时会付什么代价？**

- 提示：回想 YOLO 那道题——生成侧的表现其实**很好**，可答案里连可运行代码都没有。坏的到底是哪一段。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q2 题

**Q3. 有人从"20 万 token 以内可以全塞"推出"MaixPy 中文教程约 20–22 万 token，所以必须做 RAG"。这个推理在哪一步跳了？本项目为什么把 20 万这个数字当假设而不是结论？**

- 提示：把"这份语料一共有多少 token"和"这一次请求我打算装多大范围"当成两个不同的问题。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q3 题

**Q4. 另一个队友的方案是把提示词写得更严厉——连着五行"绝对不要编造 API，不确定就说不确定"。这为什么也拦不住幻觉？**

- 提示：模型吐下一个 token 的那一刻，它做的是**查表**还是**续写**。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q4 题

## 二、工程问答（考局限性 / 选型 / 取舍 / 边界）

**Q5. 你要给一个只服务 MaixCAM 外设开发者的内部工具做选型：语料就是 `peripheral` 那 10 篇（本地快照实测 73,768 字节，约 2 万 token），每天被问几十次。全塞 prompt 和上 RAG，你选哪个？**

- 提示：先把两笔账分开算——"每轮要付多少 token"和"改了文档之后要重建什么"，两笔账的量级不一样。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q5 题

**Q6. 换一个场景：给整个 MaixPy 中文 wiki 做同样的助手（本地快照 119 篇，中文教程约 20–22 万 token）。同事说"全塞更省事，反正检索也是从同一批文档里挑"。这个方案会在哪一步坏掉？你能接受的边界划在哪？**

- 提示：先算一次请求要装多少 token，再想这个数字随时间往哪边走。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q6 题

**Q7. 有没有哪一类幻觉，是把权威文档喂到模型眼前也救不回来的？举一类 MaixCAM 场景下的例子，并说明为什么喂资料对它无效。**

- 提示：文档里压根没写的地方，或者文档写的和板子上真实状态不一致的地方。
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 Q7 题

## 三、动手题

**H1. 把 `eval/datasets/seed.jsonl` 里的 `must_not_contain` 按"串了哪个生态"分一遍类，再找出至少一处官方的正确写法。**

- 提示：四格是 OpenCV / 树莓派 / K210 时代 MaixPy v1 / 编造不存在的方法。分完之后留意**有一格是空的**——去 `maixrag/agent/prompt.py` 里找它被写在哪。
- **验收标准**：
  1. 报出"18 题里带非空 `must_not_contain` 的有几题"这个数；
  2. 四格里**有且只有一格是空的**——指出是哪一格、它在评测集里为什么空，并说清"写了纪律 ≠ 测了纪律"指的是哪一处纪律（给出文件与行号）；
  3. 至少一条禁项能在 `corpus/raw/repo/` 或 `corpus/raw/api/` 里找到对应的官方原文（给出文件路径 + 原句或行号）。
- 依据：[tutorial 01 §4.1 / §5 / §6](../../tutorial/01-失败是什么样的.md) · [`eval/datasets/seed.jsonl`](../../../eval/datasets/seed.jsonl) · [`maixrag/agent/prompt.py`](../../../maixrag/agent/prompt.py)
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 H1 题

**H2. 亲手量一遍语料：先写下"落在 20 万 token 阈值哪一侧"的预测，再去验证。**

- 提示：token 只能估算，所以先把唯一的假设参数（中文占字节的比例）写下来再算；**两档要分开量**——全量，以及你真正打算塞进 prompt 的那个范围。
- **验收标准**：
  1. 用 [tutorial 02 §4.1](../../tutorial/02-把手工流程变成系统.md) 的命令报出 `corpus/raw/repo` 的篇数与字节数；
  2. 单独报出 `corpus/raw/repo/peripheral` 这一档的篇数与字节数；
  3. 两档都写出估算 token 与"越线 / 未越线"的判断，并写出你用的 `cjk_share`；
  4. 能说出本地快照的字节数与设计阶段的 713,520 字节**为什么不是同一个口径**。
- 依据：[tutorial 02 §4.1 / §4.2](../../tutorial/02-把手工流程变成系统.md) · [design 00 §5.4](../../design/00-项目定位与教学大纲.md) · [`scripts/measure_corpus.py`](../../../scripts/measure_corpus.py)
> 参考答案：[answers/00-为什么需要RAG.md](../answers/00-为什么需要RAG.md) 第 H2 题
