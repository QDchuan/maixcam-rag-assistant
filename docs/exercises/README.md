# 习题册

> 这一层回答的是：**我到底懂没懂。**
>
> 它**不引入新知识**。每一道题的依据都能在概念文档、事故档案或 tutorial 章节里找到——
> 找不到依据的题，是出题人的问题，不是你的。

习题按九章概念文档组织，章号 00–08。每章概念文档末尾都有一节
**「这一章留下的问题」**，那里的问题就是这里的题。

---

## 1. 怎么用这套习题

三种用法，对应三种不同的目标。

### 1.1 读完一章，当场自检

概念文档末尾那节「这一章留下的问题」就是自检清单。**读的时候先别往下翻**，
先在心里答一遍；答不出来的那几条，就是你刚才读漏的地方。这时候再回去重读那一节，
比从头再读一遍有效得多。

### 1.2 一个模块学完之后，成组做

想做完整的自检，按章从 `concepts/` 里挑一组题。建议：

| 你想确认的事 | 做哪些题 |
| --- | --- |
| 框架和流程有没有建立起来 | 概念问答 |
| 会不会做技术取舍 | 工程问答 |
| 手上的系统真的能跑通 | 复现题（在 tutorial 章末） |
| 改动一个变量会发生什么 | 改造题（在 tutorial 章末） |

四类题的定位与验收见 [第 4 节](#4-四类题与它们的验收标准)。

### 1.3 排障时反查

遇到一个现象（"召回率莫名偏低"、"某个指标是 0.000"），可以先看
[事故档案的症状索引](../postmortem/README.md)，
再回来做对应的那道题——把"我查到了原因"变成"我能说出为什么"。

## 2. 为什么题目和答案物理分离

两个目录，两个用途：

```
docs/exercises/
├── concepts/        题目（按章分文件）
└── answers/         答案（同名文件）
```

**问答题的全部价值在于"先自己想"。** 答案放在题目下面，你会在读到问题的同一秒
看到答案——思考这一步根本不会发生，而那一步正是这套题唯一想买到的东西。

所以答案在另一个文件里。但**分离不等于难找**：每道概念文档末尾都写着答案在哪一行，
这份 README 的[对照表](#6-九章对照表)也写着。你随时可以翻，只是**翻之前先答一遍**。

## 3. 为什么改造题和工程问答值钱

这套题里最有价值的不是"能答对"，而是**你会答错**。

改造题的验收标准是**预测与实测一致**，也就是说它要求你先写下预测，再动手。
工程问答没有唯一正确答案，它要的是**代价分析**和**失效条件**。

这两类题的共同点是：**给答案之前，先给判断**。

举个本项目的真实例子（[tutorial 04](../tutorial/04-检索与消融.md) 的 R2）：
查询"MaixPy 里怎么做 YOLO 物体检测"，`zh/vision/yolov5` 这一篇
在只 dense 时排第 5、在只 bm25 时排第 6，而 **RRF 融合之后掉到第 12、丢了**。

大多数人的直觉是"融合只会更好"。**直觉在这里是错的，而且错得很有信息量**：
融合先各取 20 个候选再重排，两路都把它放在 5–6 名，
而排在它前面、两路都认可的片段被叠加了分数，于是反超了它。
——如果不先写下"融合应该能救回它"，你就只会看到一个数字，
不会看到"融合会挤掉单路已经进榜的片段"这条规律。

**"预测错了"是最有价值的学习时刻，而绝大多数教学文档不给你犯错的机会。**
它们给你结论，你点头，然后合上。这套题刻意反过来：先让你押一个方向，再让实测打脸。

所以做 C 组（改造题）时有一条纪律：**动手之前，把预测写下来。**
写在纸上、写在命令旁边都行，唯一不能做的是"跑完了再说我本来就认为是这样"。

## 4. 四类题与它们的验收标准

| 类型 | 在哪 | 验收标准 | 不合格长什么样 |
| --- | --- | --- | --- |
| **概念问答** | `exercises/concepts/` | 答案覆盖到**推理链的关键环节** | 只给结论，或者把结论当原因 |
| **工程问答** | `exercises/concepts/` | 答案含**代价分析**与**失效条件** | "看情况"、"看需求"、只说贵不说不值 |
| **复现题** | 各 tutorial 章节末，编号 `A*` / `R*` | **输出与期望一致** | "大概跑了一下"、"结果差不多" |
| **改造题** | 各 tutorial 章节末，编号 `C*` | **预测与实测一致**；不一致时能说出是哪一步想错了 | 只报实测结果，没写过预测 |

### 4.1 概念问答：验收的是推理链，不是关键词

概念类答案考的是**框架、流程、算法、术语**。它的判据不是"你有没有说出那个词"，
而是**你的答案有没有走过关键的那几步**。

所以答案里会写两组提示：

- **"如果你答到了 X"** —— 说明你理解到了这一层；
- **"如果你答成 Y"** —— 那是把结论当原因，需要回去重读某一章。

比如"为什么函数名精确匹配这类查询，稠密检索经常输给 BM25"，
答到"语义压缩 / 标识符罕见 / 词面 vs 语义"才算过；
答成"因为 BM25 更准"，那是把结论当原因——回去读
[`concepts/03`](../concepts/03-检索-稀疏与稠密.md)。

### 4.2 工程问答：验收的是代价与失效条件

工程类答案考的是**局限性、选型、取舍、排障**。这类题**没有唯一正确答案**，
（在 [design 07 的 2×2](../design/07-文档体系设计.md) 里它们是右列）
所以它的答案结构不一样：

```
判断依据        这几条都考虑到，才算合格
一个示范回答    用本项目的真实数字说话（不是通用例子）
常见的浅答案    以及为什么浅
```

**"常见的浅答案"是这类答案的核心。** 它通过对比教学：
你看到自己那个答案为什么不够好，比看到一个"标准答案"有用。

而"没有代价分析的方案描述，一律不算合格"——这句话在这套题里是硬标准，
不是修辞。它会具体到这一步：**你选的方案，在什么条件下会失效？**

### 4.3 复现题：验收的是"输出与期望一致"

复现题在各 tutorial 章节末，编号是 `A1` / `A2` / `R1` / `R2` 这种。
它们的要求很硬：**跑命令，输出与期望一致**。

| 例子 | 出处 | 验收 |
| --- | --- | --- |
| R2 用 `demo_retrieval.py` 记录 `zh/vision/yolov5` 在 dense / bm25 / fused 三列的名次 | [tutorial 04](../tutorial/04-检索与消融.md) | 能复现"dense 第 5 / bm25 第 6 / fused 第 12"，并说出多出来的那 6 名从哪来 |
| A2 跑 `check_symbols_demo.py`，把 7 条用例分成"应放行 / 应抓到" | [tutorial 01](../tutorial/01-失败是什么样的.md) | 7 条全部 ✅，白名单条数为 4868 |
| A2 跑一次只测检索轴的评测 | [tutorial 05](../tutorial/05-评测.md) | `signature` 行是 **0.500**，不是 0.000 |

注意第三条：**期望值是一个具体的数字，不是一个"看起来不错"**。
对数字之前，先在报告里把那个值找出来——报告在
[`eval/results/`](<../../eval/results/rag_L1_rag[rrf_bm25].md>) 里，
对不上时先分清是语料变了、检索配置变了，还是你跑的是另一个 `--fake*` 开关。
（那份报告是只跑 BM25 的，`signature` 行是 **0.000**——正好也是
[`concepts/03`](../concepts/03-检索-稀疏与稠密.md) 误解三"召回率低不能靠加大 top_k 解决"的现场证据。）

### 4.4 改造题：验收的是"预测与实测一致"

改造题（`C*`）是四类里学习效率最高的。它改一个参数、修一个 bug、或者做一次取舍实验，
然后比较**你事先说的**和**实际发生的**。

验收标准只有一条：**预测与实测方向一致；不一致时，你能说出是哪一步想错了。**

它为什么比复现题值钱，看这个例子就清楚了（[tutorial 03 · C1](../tutorial/03-语料工程.md)）：
把 `chunking.strategy` 从 `heading` 改成 `fixed`，代码块与表格 chunk 双双归零，
按直觉分数该降——**本机实测却是总体 Recall@5 从 0.611 升到 0.694**，
concept 从 0.500 升到 0.688。

如果你预测"会降"，答对与否不重要，重要的是你能不能说清：
`kind` 不参与打分，但 code chunk 没了会改变 BM25 的文档长度归一化与 token 池。
**这就是"预测错了"的价值**——它逼你去看那个你原本忽略的机制。

## 5. 每道题都带三样东西

tutorial 章末的动手题统一是这个形态：

```markdown
**C2（改造）** 把 `retrieval.top_k` 从 5 改到 20 再跑一次，
预测 `context_precision` 与 `recall` 各会怎么动。

- 提示：多出来的名额是给谁的
- 验收：预测两个方向都正确
- 依据：concepts/03 误解三
```

| 每道题带什么 | 干什么 |
| --- | --- |
| **提示** | 卡住的时候看，它给方向不给答案 |
| **验收** | 怎么知道自己做对了 |
| **依据** | 去哪找根据——概念文档、事故档案、代码 |

概念问答的答案里还有第四样：**"常见的浅答案"**，见 [4.2](#42-工程问答验收的是代价与失效条件)。

> **一条纪律：这里没有填空题，也没有"请解释什么是 X"。**
> 每一道题都对应一个真实会发生的工作场景——MaixCAM / MaixPy 的语料、真实的评测数字。
> 要么是"你会怎么做"，要么是"这个现象说明了什么"。
> 出题不用通用例子（"假设你在做电商客服"），因为读者要做两次翻译，
> 而翻译过程正是理解流失的地方。

### 6.2 关于文件名（一个还没统一的点）

`concepts/` 与 `answers/` 的文件名目前**没有对齐**：概念文档的链接与 `concepts/` 下
实际的文件名在三章上不一致——概念文档指 `03-检索-稀疏与稠密.md` / `05-生成与忠实性.md` / `07-评测-两条轴.md`，
而实际文件名是 `03-检索-稀疏与稠密.md` / `05-生成与忠实性.md` / `07-评测-两条轴.md`；
tutorial 04、05、07 章末都指向了一个当前并不存在的 `07-评测-两条轴.md`
（04 章末还多指向一个 `04-融合与重排序.md`；06 章末则直接写成"该文件**待写**"）。

上表按**磁盘上真实存在的文件**写。`answers/` 下的文件名目前以各章概念文档末尾
给出的名字为准；命名统一（一章一个名字，概念 / 习题 / 答案三处一致）是
[`design/07`](../design/07-文档体系设计.md) 第 4.4 节那条规则的执行问题——
等这条规则真的被工具检查起来（[`design/07` §5.1](../design/07-文档体系设计.md) 的链接检查），
它会自己浮出来。
