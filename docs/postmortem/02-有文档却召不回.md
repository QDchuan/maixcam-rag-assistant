# 02 · 有文档却召不回

> **类别**：语料与检索
> **教的是**：文档存在 ≠ 能被召回
> **对应代码**：`maixrag/corpus/pipeline.py` 的 `_api_chunks`

---

## 症状

第一份完整的检索轴评测报告里，按问题类型分组是这样的：

```
| qtype       | n | Recall@K |
| ----------- | - | -------- |
| concept     | 8 | 0.625    |
| example     | 4 | 0.750    |
| signature   | 4 | 0.000    |   ← 完全为 0
| troubleshoot| 2 | 1.000    |
```

`signature` 类——也就是"某个函数的参数是什么"这类问题——**召回率是 0.000**。

而语料里**明明有 API 参考文档**。54 个 API 页面已经抓下来了，符号也抽出来了，
白名单也建好了。

## 它为什么危险

因为"文档在语料库里"和"文档能被召回"是两件不同的事，而它们**看起来一样**。

你打开 `corpus/raw/api/` 一看，文件都在。于是你不会怀疑语料，
而会去调检索算法——换嵌入模型、调 top_k、加 rerank。

**全都在错的方向上。**

这个事故还有一个更隐蔽的地方：**总分看起来是正常的**（Recall 0.611）。
如果你只看总分，会得出"检索基本可用，小幅优化即可"的结论。
是**按 qtype 分组**才让这个问题暴露出来。

## 怎么发现的

从"一个不合理的 0"开始的。

`signature` 是 0.000 而不是 0.3 或 0.5——**完全没有命中过任何一次**。
这不符合"检索质量一般"的特征，而符合"这类问题在语料里根本没有答案"的特征。

于是我去查：评测集里 `signature` 类问题的 `required_docs` 是什么？
答案是 `api/maix.camera` 这样的 doc_id。

**然后是关键的一步**：我去索引里搜有没有这个 doc_id。

```python
chunks = load_chunks(Path('corpus/processed/chunks.jsonl'))
print(sum(1 for c in chunks if c.doc_id.startswith('api/')))
# 0
```

**一个都没有。** API 参考页产出了 1898 个符号、2996 条白名单，
但**没有产出任何一个可检索的 chunk**。

## 根因

管线当时把两条通道的产物形态设计成了不同的：

| 通道 | 产物 | 用途 |
| --- | --- | --- |
| 教程（仓库 Markdown） | `chunks.jsonl` | 可检索的散文、代码、表格 |
| API（文档站 HTML） | `api_symbols.jsonl` + `api_roster.txt` | **只用于防幻觉校验** |

API 通道的产物被当成"校验用的元数据"，而不是"可检索的内容"。
所以它从来没进入索引。

而这个设计错误背后有一个**看似合理的直觉**：
"API 文档就是签名列表，用户问签名的时候模型能直接答，不需要检索。"

**这个直觉错在哪**：模型需要**先读到签名**才能答。
如果签名不在检索结果里，模型根本看不到它——
它只能凭记忆猜，那正是我们要防的幻觉。

## 修复

让每个 API 符号渲染成一个可检索的 chunk（`pipeline._api_chunks`）：

```python
text = "\n".join(filter(None, [
    symbol.qualname,      # maix.camera.Camera.__init__
    symbol.signature,     # def __init__(self, width: int = -1, ...) -> None
    symbol.summary,       # Construct a new Camera object...
    symbol.params,        # item | description | type | func | param | width : ...
]))
```

**四样内容缺一不可**，各有各的用途：

| 内容 | 检索时的作用 |
| --- | --- |
| 限定名 | 精确匹配标识符查询（"maix.camera.Camera"） |
| 签名 | 参数名匹配（"width height 参数"） |
| 说明文字 | 自然语言匹配（"怎么创建摄像头对象"） |
| 参数表 | 语义匹配（"宽度怎么指定"） |

只放签名的话，用自然语言提问就召回不到；只放说明的话，精确查符号会失败。
**两者缺一，要么召回不到，要么召回不准。**

## 结果

同一评测集、同一配置，**只改语料这一项**：

| qtype | 修复前 | 修复后 | 变化 |
| --- | --- | --- | --- |
| **signature** | **0.000** | **0.500** | **+50 pt** |
| example | 0.250 | 0.750 | +50 pt |
| troubleshoot | 0.000 | 1.000 | +100 pt |
| **concept** | 0.625 | **0.500** | **−12.5 pt** |
| 总体 Recall@5 | 0.556 | 0.611 | +5.5 pt |

chunk 总数 1940 → 3838。

**注意 concept 类的下降**——这不是意外，而是这个修复的**真实代价**：
新增的 1898 个 API chunk 抢占了 Top-5 的名额，
把概念类问题需要的教程散文挤了出去。

> **这就是"加语料层不是免费的"。** 而只看总分的 +5.5pt 完全看不出这件事。

## 回归测试

**位置**：`maixrag/corpus/pipeline.py`

```python
api_chunks = self._api_chunks(symbols, manifest)
chunks.extend(api_chunks)
```

以及 `corpus/reports/stats.md` 里固定输出的 `signature` chunk 数量——
它是一个**可见的信号**：如果哪天它变成 0，报告会立刻显示出来。

## 同类问题清单

| 变体 | 表现 |
| --- | --- |
| 文档在库里但没进索引 | 建索引时漏了某个来源（本项目这一条） |
| 进了索引但被过滤掉 | 元数据过滤条件太严，实际把内容全滤掉了 |
| 索引了但 chunk 太小 | 关键信息被切散，检索到了也没用 |
| 索引了但 chunk 太大 | 噪声淹没信号，排名靠后 |
| 检索到了但没进上下文 | top_k 太小，或去重把相关内容合并掉了 |

**一条通用排查路径**：

```
召回率异常低
  → 先查"这个 doc_id 在索引里存在吗"（本项目就是这一步发现的）
  → 再查"它在 Top-K 里出现过吗、排第几"
  → 最后才去怀疑检索算法
```

**先怀疑语料，再怀疑算法。** 算法再好在空语料上也检不出东西。

## 课后习题

**A1（复现）** 跑 `python -m maixrag --config configs/l2_hybrid.yaml corpus build`，
在 `corpus/reports/stats.md` 里找到 signature chunk 的数量。
然后打开 `corpus/processed/chunks.jsonl`，找出一个 `kind` 为 `signature` 的 chunk，
看看它的 `text` 里都有什么。

- 验收：能说出四样内容（限定名/签名/说明/参数表）分别在什么查询下起作用

**B1（诊断）** 假设你把 `_api_chunks` 里的 `summary` 和 `params` 去掉了，
只留 `qualname` 和 `signature`。预测哪些类型的查询会退化，说明理由。

- 验收：能指出"自然语言提问"这一类，并解释词面不重合的问题
- 相关：[03 语料工程](../tutorial/03-语料工程.md)

**C1（改造）** 试着把 API chunk 和教程 chunk 分别建索引
（让它们各自有独立的 Top-K 名额，而不是互相挤）。
预测两条轴会怎么变，然后实际验证。

- 验收：预测与实测方向一致；若不一致，能说出是哪一步想错了
- 提示：想一想"独立名额"和"统一排名后取前 K"在什么情况下等价、什么情况下不等价
- 这是本项目**L4 查询路由**的思路，做完你就理解了它的动机

**D1（判断）** signature 类 +50pt 换来 concept 类 −12.5pt。
如果你的用户里 80% 的人问的是概念类问题，你会怎么选？

- 验收：答案里必须包含代价分析与适用条件，不能只说"我选 A"
- 提示：注意问的是"你的用户里 80%"，而不是"评测集里 80%"

**D2（判断）** 这篇事故的核心结论是"先怀疑语料，再怀疑算法"。
但反过来，什么时候应该**先**怀疑算法？

- 验收：能给出一个明确的判据（什么现象指向算法而不是语料）
