# 05 · 伪装成好消息的 0

> **类别**：失败处理
> **教的是**：指标必须暴露覆盖面
> **对应代码**：`scripts/inspect_eval.py`、`maixrag/evaluation/harness.py`

---

## 症状

完整两轴评测报告里，生成轴这一栏：

| 指标 | 值 |
| --- | --- |
| 引用精确率 | 0.889 |
| 引用召回率 | 0.889 |
| 触发禁止项比例 | 0.000 |
| **符号级幻觉率** | **0.000** |
| 拒答率 | 0.000 |

**"符号级幻觉率 0.000"看起来是好消息**——模型一个 API 都没编造。

而这一栏正是本项目最核心的防幻觉指标。0.000 意味着"防幻觉机制完全成功"。

## 它为什么危险

因为 **0.000 有两种完全不同的含义**：

1. **真的很好**：检查了 200 个符号，全部存在；
2. **几乎没测到东西**：一共只检查了 0 个符号。

**这两种情况在报告里长得一模一样。**

而这个区别决定了完全相反的行动：

| 真相 | 该做什么 |
| --- | --- |
| 真的很好 | 可以把这个配置推向下一步 |
| 没测到东西 | **报告本身不可信**，先修覆盖率 |

如果把它当成"真的很好"，你会基于一个**空测量**做出技术决策。

## 怎么发现的

因为 0.000 **太好了**。

一个真实模型在真实问题上，幻觉率恰好是 0，而且是在 18 道题上——
这个结论需要证据支撑。所以我写了 `scripts/inspect_eval.py`，
专门去问一个问题：**"这条指标实际覆盖了多少题？"**

跑出来的结果：

```
生成轴（注意看覆盖了多少题——0.000 可能只是「没测到」）
  **符号被检查到的题数  0/18  (0%)**
  ⚠️ 没有任何题目被检查到符号——幻觉率 0.000 不具参考意义
```

**0/18。** 它一个符号都没检查过。

## 根因

两层，第一层是代码的，第二层是**指标设计**的。

### 第一层：为什么是 0

因为模型**没有写代码**。

用同一批问题看答案就知道原因了——模型对"怎么做 YOLO 检测"的回答是：

> 资料中没有给出 YOLO 物体检测的完整代码，因此无法提供可直接运行的完整示例。

它按纪律拒答了。而**没有代码，就没有 `maix.*` 符号可检查**。

再往下追：它为什么拒答？因为**检索没有召回含例程的那篇文档**
——这正是事故 [02 有文档却召不回](./02-有文档却召不回.md) 描述的现象，
只不过这里影响的是另一个指标。

**所以这个 0.000 是一次检索失败的"下游症状"。**

### 第二层：为什么报告没告诉你

指标的定义是这样的：

```python
@property
def hallucination_rate(self) -> float:
    if self.symbol_checked == 0:
        return 0.0          # ← 没有检查到东西时，返回"完美"
    return len(self.unknown_symbols) / self.symbol_checked
```

**没有样本时返回 0.0。** 从代码角度它不算错——
避免了除零，而且语义上可以解释为"没有发现幻觉"。

但从**报告的角度**它有一个致命问题：

> **它把"没有证据"和"证据表明没问题"编码成了同一个数字。**

## 修复

**没有改指标公式**（改了反而会让下游拿不到数字）。
改的是**让覆盖面必须出现在报告里**：

新增 `scripts/inspect_eval.py`，它对每条指标打出**覆盖了多少题**：

```
检索轴
  有召回片段的题数      18/18
  至少命中一次的题数    12/18
  Recall@K              0.611

生成轴（注意看覆盖了多少题——0.000 可能只是「没测到」）
  **符号被检查到的题数  0/18  (0%)**
  ⚠️ 没有任何题目被检查到符号——幻觉率 0.000 不具参考意义
  有引用的题数          16/18
  拒答题数              0/18
```

并且当覆盖率为 0 时，**显式打印警告**。

修完后的真实数字是 **符号被检查到的题数 18/18**（修了事故 02 的检索问题之后），
幻觉率 0.000 —— **这一次它是真的**，因为覆盖面是满的。

> **同一个数字，修复前是"没测到"，修复后是"真的很好"。**
> 区别不在数字，在覆盖面。

> ⚠️ **上面这段输出今天无法用一条命令复现，此条待补。**
> 它对应的是 `eval/results/rag_L1_rag[rrf_dense+bm25]` 那次运行
> （可对齐的三项：`Recall@K 0.611`、`拒答率 0.000`、`引用精确率 0.889`
> 即"有引用 16/18"），而那次运行的 `.json` 已按证据层的第 3 条维护纪律
> 删掉（见 [`docs/evidence/README.md`](../evidence/README.md)），只剩同名 `.md`——
> `.md` 不带"覆盖了多少题"这几列，**这些数字没有可复核的出处**。
> 本节最后那句"符号被检查到的题数 18/18"同理：它出自同一份已删除的产物。
> 现在磁盘上能复现的快照是 `python scripts/inspect_eval.py`
> （默认读最新的 `eval/results/agent_loop.json`）：
> `符号被检查到的题数 16/18 (89%)`、`有引用的题数 18/18`、`拒答题数 8/18`。
> 两次数值不同是因为被评链路不同（链式 L1 vs agent 循环），
> 不是结论不同——它们说的是同一件事：**覆盖率必须打出来**。

## 回归测试

**位置**：`scripts/inspect_eval.py`

它的存在本身就是回归保护：任何一次评测之后跑它，
覆盖率异常会立刻显示出来。

同类做法在项目里还有几处（都是"让覆盖面可见"）：
- `corpus/reports/roster_gaps.md` —— 白名单漏了哪些 import 写法
- `corpus/reports/stats.md` —— 各类 chunk 的数量（某个变成 0 立刻可见）
- `Report.by("qtype")` —— 分组指标，防止整体分数掩盖局部问题

## 同类问题清单

| 变体 | 表现 |
| --- | --- |
| 空集合的平均值 | `sum([])/len([])` 被特判成 0，看起来"完美" |
| 全被过滤掉 | 过滤条件太严，样本数变 0 但报告照常出 |
| 断言没执行 | 测试通过了，但那个测试被 skip 了 |
| 断言永真 | `assert x or True` 这类，永远通过 |
| 分母为 0 | 准确率、召回率的经典陷阱 |
| 覆盖率缺口 | 只在某个子集上评测，却报告成整体结果 |

**一条通用做法**：任何比率型指标，**同时报告分子、分母**。

> 只报"幻觉率 0.000"没有意义；
> **报"幻觉率 0.000（检查了 0/18 题）"才有意义。**

后者会立刻让人发现问题——**因为它把"没有证据"暴露出来了**。

## 课后习题

**A1（复现）** 用假对话模型跑一次评测，然后跑 `inspect_eval.py`：

```bash
python -m maixrag --config configs/l2_hybrid.yaml eval --level rag --fake-chat
python scripts/inspect_eval.py
```

- 验收：能看到"生成轴未被真实测量"的警告，并说出它是怎么被判断出来的
- 提示：假客户端返回空答案，所以没有代码可检查

**B1（诊断）** 一份评测报告显示"引用精确率 1.000"。
列出至少三种"这个 1.000 其实没有意义"的情况。

- 验收：每种都指出对应的覆盖面指标是什么
- 提示：想一想"一个引用都没有"和"引用全部有效"在公式上是不是同一个值

**C1（改造）** 给 `Report.to_markdown()` 加一列"覆盖题数"，
让每条指标都带上分母。

- 验收：报告里不再有任何"没有分母的比率"
- 相关：`maixrag/evaluation/harness.py` 的 `Report._agg`

**C2（改造）** 现在只有幻觉率有覆盖率保护。
检查一下还有哪些指标有同样的风险（分母可能为 0），列出来并逐一处理。

- 验收：`citation_precision`、`citation_recall`、`context_precision`、`recall`
  这几个都要被检查到

**D1（判断）** 有人主张"没有样本时应该返回 `None` 而不是 `0.0`"。
你同意吗？说明它对**下游消费者**（报告、阈值判断、自动回归门禁）的影响。

- 验收：要分别讨论"给人看的报告"和"给程序判断的门禁"两种消费者
- 提示：`None` 会让"分数低于阈值就报警"这类逻辑崩掉，这是不是好事

**D2（判断）** 本项目的评测器有一条纪律："能程序判的指标不要交给模型判"。
覆盖率检查属于哪一类？它能不能被自动化到"不需要人记得去跑 inspect_eval"？

- 验收：给出一个"默认就带覆盖率"的报告设计
