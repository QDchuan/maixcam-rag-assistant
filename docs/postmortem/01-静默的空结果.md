# 01 · 静默的空结果

> **类别**：失败处理
> **教的是**：安静的成功是假象
> **对应代码**：`maixrag/corpus/fetch.py` · `scripts/measure_corpus.py`

---

## 症状

运行语料抓取脚本，它打印：

```
[zh]    0 篇          0 字节  约   0.0 万 tokens
[en]    0 篇          0 字节  约   0.0 万 tokens
```

**退出码是 0。没有报错，没有警告，没有异常。**

如果你不看那一行数字，会以为抓取成功了、只是语料确实为空。

## 它为什么危险

这是所有失败模式里最坏的一种：**它伪装成成功。**

- 一个会抛异常的失败，你会立刻去修；
- 一个安静返回空结果的失败，你会**基于它继续往下走**——
  建一个空索引、跑一次评测、得到一堆 0 分的报告，
  然后花几个小时怀疑是检索算法的问题。

而这个事故发生在**最不该出错的地方**：语料是一切的下游基础。
它错了，后面所有结论都建立在空数据上。

## 怎么发现的

不是因为报错——是因为**数字不合理**。

当时的预期是"中文教程大约 130 篇"。脚本报告 0 篇，
而这个数字与已知事实矛盾，所以我去查了。

**这一步是整篇事故里最值得记的**：如果当时没有"预期是多少"这个参照，
0 篇看起来就像"这个仓库没有文档"，而不是"我的代码错了"。

> **教训**：跑任何脚本之前，先想清楚"合理的输出长什么样"。
> 没有这个参照，异常的输出会被当成正常的输出。

## 根因

GitHub 的 git-trees API 返回的 `path` 是**相对于该子树根**的：

```python
# 实际拿到的是（子树是 docs/doc/zh）
'README.md'
'vision/camera.md'
'ai_model_converter/maixcam.md'

# 而我按仓库全路径过滤
if e["path"].startswith("docs/doc/zh/"):   # ← 永远匹配不上
```

于是筛选结果为空。**而"筛选结果为空"和"语料为空"在这段代码里长得一模一样。**

这个 API 行为不算错——它返回相对于所查询节点的路径，是合理的。
错的是我假设了它是绝对路径，而且**没有对这个假设做任何检查**。

## 修复

两处，缺一不可：

**第一，逻辑改对。** 按子树相对路径处理
（`maixrag/corpus/fetch.py` 的 `_known_doc_paths`、`scripts/measure_corpus.py` 的 `summarize`）：

```python
md = [e for e in entries if e["path"].endswith(".md")]
```

**第二，也是更重要的一处：让空结果显式失败。**

```python
if not files and known:
    raise FetchError(
        f"CDN 通道已有 {len(known)} 个已知文件名却一个都没取到——"
        f"网络或 CDN 结构可能变了，不能当成'语料为空'"
    )
```

同样的防御加在了每一个可能产生空结果的地方。原则是：

> **空结果必须是一个错误，不能是一个答案。**

**位置**：`maixrag/corpus/fetch.py` 内联断言 + `maixrag/corpus/pipeline.py`

if not md:

## 同类问题清单

这个坑在你自己的项目里可能以这些形式出现：

| 变体 | 表现 |
| --- | --- |
| 文件读取返回空 | `open().read()` 拿到空串，被当成"文件是空的" |
| 检索返回空 | 向量库里没数据，检索返回 `[]`，下游当成"没找到相关内容" |
| 解析返回空 | HTML 结构变了，解析出 0 个元素 |
| 过滤条件写错 | 时间范围、状态枚举写错，返回空集合 |
| **指标的分母是 0** | 见 [05 伪装成好消息的 0](./05-伪装成好消息的0.md) |

**一条通用做法**：在任何"可能合理地返回空"的地方，
把"空"和"错"分开表达。空是一个值，错是一个异常。

## 课后习题

**A1（复现）** 故意制造一次静默的空结果：把 `fetch_repo_docs` 里的路径前缀
改回 `docs/doc/zh/`，重跑，观察它的输出与退出码。

- 验收：能得到"0 篇 + 退出码 0"，并说出为什么这比抛异常更危险
- 提示：注意它**不会**因为你改错了而报错

**C1（改造）** 给 `scripts/measure_corpus.py` 的 `summarize` 加一个检查：当传入的条目非空、但过滤后为空时，
抛出一个带诊断信息的异常。诊断信息里应该包含什么？

- 验收：异常信息足以让人在不读源码的情况下定位问题
- 相关：`maixrag/corpus/pipeline.py` 的 `check_roster_covers_corpus`

**D1（判断）** 有人说"防御性检查会让代码变啰嗦，应该只在关键路径上加"。
你同意吗？用本项目的例子说明你的判断依据。

- 验收：答案里必须说清"关键路径"的判据，以及漏判的代价
