# 03 · 语料工程

> 这一章要你动手做一件事：**把 MaixPy 的语料抓到本地、切成 chunk、抽出符号白名单，
> 然后亲手看到"语料决定检索上限"。**
> 本章全程不改检索算法——你会看到，召回归零与召回跃升都可以只由语料引起。
>
> 前置：[concepts/02 语料与切分](../concepts/02-语料与切分.md)（语料分层与切分纪律）·
> [concepts/03 检索：稀疏与稠密](../concepts/03-检索-稀疏与稠密.md)（召回为什么是主指标）。
> 这一章只讲**怎么做**，不重复那两章的论证。

---

## 1. 一句话结论

**语料工程就是"亲手造出可检索空间"**：没被切成 chunk 的内容，在检索器眼里根本不存在。
所以顺序永远是**先让语料里"有东西可召回"，再谈怎么排得更准**——
本项目两次最大的召回跃迁都来自这一步，检索代码一行没改。

## 2. 为什么需要这一步

因为**语料坏了，后面每一步都在错的方向上努力**。

没有语料工程时，最常见的三个动作是换嵌入模型、调 `top_k`、加 rerank。
它们都假设"答案已经在索引里，只是没排上来"。而本项目第一次评测就撞上反例 [本项目实测]：

```
| qtype        | n | Recall@K |
| concept      | 8 | 0.625    |
| example      | 4 | 0.750    |
| signature    | 4 | 0.000    |   ← 一次都没命中
| troubleshoot | 2 | 1.000    |
```

`signature`（"`find_blobs` 的参数有哪些"）不是"排得低"，是**语料里根本没有这类 chunk**：
56 页 API 参考被用来生成白名单，却**没产出任何一个可检索 chunk**。
文件在磁盘上、符号抽了 1898 个、退出码 0，召回率是 0.000（详见 [事故 02](../postmortem/02-有文档却召不回.md)）。

**这就是它要单独一章的理由**：它坏起来不报错，只有按 `qtype` 分组看才暴露。

## 3. 怎么做

### 3.1 先认领本地，再决定要不要联网

本仓库 `corpus/raw/` 里已有一份快照（119 篇教程 + 56 页 API）。
**第一步永远是从磁盘认领清单，而不是重新抓**：

```bash
# 从已落盘的文件重建 corpus/manifest.json（断点续抓的核心动作）
python -m maixrag --config configs/l2_hybrid.yaml corpus adopt

# 解析 + 切分 + 抽 API 符号，产出 processed/ 与 reports/
python -m maixrag --config configs/l2_hybrid.yaml corpus build
```

`adopt` 的存在理由很实际：抓取会被网络、配额、带宽打断，而 `build` 需要一份清单。
它**不检查上游是否有更新**——认领以本地为准；要拿最新版走 `corpus fetch`。

### 3.2 要联网时：两条通道 + 降级路径

仓库教程与 API 参考的获取方式不同，这是上游结构决定的：教程有 Markdown 原文
（`docs/doc/zh/`），API 参考由源码 docstring 生成、**不在仓库里**，只能从文档站取。

| 通道 | 目标 | 实现 | 版本固定 |
| --- | --- | --- | --- |
| 仓库 | 119 篇教程 Markdown | 整包 tarball（首选）/ 逐文件 contents API / jsDelivr CDN（降级） | 固定到 commit |
| 站点 | 56 页 API HTML | 按 `sitemap.xml` 枚举后抓取 | 只能记抓取时间与哈希 |

三条路都实现了，见 `maixrag/corpus/fetch.py`：整包一次请求拿全量、不受匿名 60 次/小时配额限制、
拿到的是同一 commit 的一致快照；逐文件通道会撞 403；CDN 通道不消耗配额但需要先知道文件名。

```bash
# 代理：优先读 MAIXRAG_PROXY，其次 HTTPS_PROXY / HTTP_PROXY
$env:MAIXRAG_PROXY = "http://127.0.0.1:7892"
python -m maixrag --config configs/l2_hybrid.yaml corpus fetch --ref main
```

大文件会中途断流（实测遇到 `IncompleteRead`），整包下载用 `Range` 头续传；
再次运行时大小一致的文件直接跳过。

### 3.3 差异报告：漂移必须显式报告

`corpus build` 每次重写 `corpus/reports/diff.md`，它**不追求"无差异"**，只追求"差异可见"：

```
- 仅站点存在：56 个
- 仅仓库存在：119 个
- 内容哈希不同：0 个
```

这 56 与 119 不是 bug：站点侧是 API 参考（`maix/camera`），仓库侧是教程（`vision/camera`），
本来就不是同一批页面。报告还如实列出拼写漂移——仓库侧边栏写 `customize_model_yolo.md`，
站点上是 `custmize_model.html`。**把它列出来，而不是猜一个"应该相同"。**

### 3.4 解析、切分与元数据

管线在 `maixrag/corpus/pipeline.py`，解析在 `maixrag/corpus/markdown.py`，切分在 `maixrag/corpus/chunker.py`。

| 动作 | 规则 | 产物 |
| --- | --- | --- |
| 解析 | AST 级（`markdown_it`）而非正则；标题建树、代码块与表格各自成块、图片替换为占位不参与检索 | 章节树 + 代码块清单 |
| 切分 | 两级：**先按标题切**，超预算的段再按段落装箱并保留重叠；**代码块与表格各自独立成段、不参与二次切分** | `processed/chunks.jsonl` |
| 元数据 | `module`、`kind`（prose / code / table / signature）、`heading_path`、`chapters`（官方 sidebar.yaml 的章节归属） | 每个 chunk 的 `meta` |
| 抽符号 | 从 API 页的 `h2/h3/h4` + `language-python` 代码块抽限定名与精确签名 | `processed/api_symbols.jsonl` + `api_roster.txt` |

三处容易漏的细节：

- **多 H1 页面要降级**：部分 MaixPy 页面每节都用 `#`，章节树是平的，标题路径失去区分度
  （`split_heading_levels` 把非首个 H1 降为 H2）。
- **API 层必须产出 chunk，不能只产出白名单**：每个符号渲染成
  `限定名 + 签名 + 说明 + 参数表`，缺一不可——只有签名，自然语言提问召回不到；只有说明，精确查符号失败。
- **切分参数是待评测项，不是旋钮**：`chunking.strategy` 只有 `heading` 与 `fixed` 两个值，
  默认 `heading`。完整参数表见 `maixrag/config.py` 的 `ChunkingConfig`。

### 3.5 白名单要收"用户实际写的写法"

`pipeline.py` 建白名单时做三件事，每件都对应一次真实误报：

1. **扁平别名**：`maix.peripheral.gpio.GPIO` → 用户写的 `maix.gpio.GPIO`（教程原文就是 `from maix import gpio`）；
2. **从语料补漏**：教程里 import 了、但 wiki 没有 API 页的模块（`maix.sensevoice` 等）也要收；
3. **覆盖自检**：每次 build 扫教程原文的 import 写法，把未覆盖的写进 `corpus/reports/roster_gaps.md`。

第 3 条是关键：**前两条修已知漏项，第三条让"漏了什么"变得可见。**

## 4. 亲眼看一次

### 4.1 看四类 chunk 的数量

```bash
python -m maixrag --config configs/l2_hybrid.yaml corpus build
```

读 `corpus/reports/stats.md`，"chunk 按类型"表里应当有**四行**：

```
| 类型 | 数量 |
| signature | 1898 |
| prose | 1268 |
| code | 605 |
| table | 67 |
```

**这四行是这一章的仪表盘。** 任何一行变成 `0`，都意味着一类问题在语料层失去了答案：
`signature` 归零 = API 层没产出 chunk（[事故 02](../postmortem/02-有文档却召不回.md)）；
`code` / `table` 归零 = 切分策略把结构标签丢了（下一节）。

同时看 `roster_gaps.md`，本机当前输出是：

```
# 白名单覆盖缺口

未发现缺口：教程里出现的 import 写法都已覆盖。
```

**空报告在这里是好消息，但它必须存在、必须被生成**——否则"没有缺口"和"没做这项检查"
长得一模一样（与 [事故 01 静默的空结果](../postmortem/01-静默的空结果.md) 同一种病）。

### 4.2 亲手看切分策略把结构标签丢掉

```bash
python scripts/demo_corpus_cut.py
```

本机实测输出（`projects/README.md`，含全文最大的一张表）：

```
策略       chunk   代码   表格   散文   '|'总数   最大token
heading      15      0      1     14       240        1223
fixed         9      0      0      9       240        1270
```

看两个数：`'|'总数` 两行都是 240，说明**表格文字一个字没丢**；
但 `表格` 那列从 1 变成 0——`kind` 全变成 `prose` 了。
**下游按 `kind` 做结构感知检索时，再也认不出这是一张表。**
换一篇：`python scripts/demo_corpus_cut.py vision/find_blobs.md`。

## 5. 证据

| 事实 | 数字 | 性质 |
| --- | --- | --- |
| API 层产出 chunk 前后 | signature 召回 **0.000 → 0.500**；concept 0.625 → **0.500**；总体 0.556 → 0.611 | [本项目实测，18 题 / 真实 bge-m3] |
| 白名单规模 | 1898 个符号 / 4868 条（含扁平别名 `maix.gpio.*` 11 条） | [本项目实测] |
| 切分改 fixed | chunk 3838 → 2812，code 605 → **0**、table 67 → **0** | [本项目实测] |
| 切分改 fixed 的召回变化 | 总体 Recall@5 **0.611 → 0.694**，concept 0.500 → 0.688 | [本项目实测] |
| 大表格不切开 | 1223 token 的表格（`zh/projects/README#h5.1`）完整成块 | [本项目实测] |

最后两行是要一起看的一句工程判断：**结构标签与召回分数是两件事，而召回分数看不出结构标签没了。**
收益（+8.3 pt 总体）与它破坏的东西（结构感知检索的物理基础）在报告里只是同一张表的两列。

## 6. 失败的样子

**一、固定长度切分：表格文字还在，但结构标签没了。**

用 `scripts/demo_corpus_cut.py` 看到的对比就是现场。根因不在 `max_tokens`，
而在 `_para_split` 只按**空行**切段——Markdown 表格的行之间是换行、不是空行，
所以整张表是**一个不可分割的"段落"**，`fixed` 只能把它整段塞进一块。
实测：改 `fixed` 后 code 与 table chunk 双双变成 **0**，而**没有任何一张表被从中间截断**。

> 两处反直觉：①它不报错，评测照跑，分数甚至更高；
> ②"表格不切开"这条纪律不是靠策略实现的，是靠"表格内部没有空行"这个偶然性质实现的。
> 一旦上游表格里出现空行，这个保证就没了——这是**已知的边界，不是已解决的问题**。

**二、只把 API 页用来生成白名单、不产出 chunk → signature 召回 0.000。**

真实事故，症状/根因/修复见 [事故 02](../postmortem/02-有文档却召不回.md)。复现它的条件只要一条命令：

```bash
python -c "import json;from pathlib import Path;c=[l for l in Path('corpus/processed/chunks.jsonl').read_text(encoding='utf-8').splitlines() if l.strip()];print('chunk',len(c),'| kind=signature',sum(1 for x in c if json.loads(x)['kind']=='signature'))"
```

当前输出 `chunk 3838 | kind=signature 1898`。
**如果这里是 0，而 `api_roster.txt` 仍有 4868 条**，你就复现了那次事故的条件：
校验能力全在，召回能力为零。

**三、白名单只收 API 文档路径 → 把正确代码判成幻觉。**

这是**假阳性**，比漏报更危险：使用者发现"我明明写对了它说我错"，就会把校验关掉，
于是真幻觉一起被忽略（见 [事故 03](../postmortem/03-校验器把正确代码判成幻觉.md)）。现在两种写法都在：

```bash
python -c "from pathlib import Path;L=[l.strip() for l in Path('corpus/processed/api_roster.txt').read_text(encoding='utf-8').splitlines() if l.strip()];print('文档路径',len([x for x in L if x.startswith('maix.peripheral.gpio.')]),'扁平',len([x for x in L if x.startswith('maix.gpio.')]))"
```

输出 `文档路径 11 扁平 11`。**故意把它写窄一点**：换成 `startswith('maix.peripheral.gpio.')`
去查 `maix.gpio.GPIO`，你会得到 `0`——那就是当时校验器眼里的世界。

**四、`adopt` 会把旧文件当成本次抓取。**

`adopt` 以本地为准、**不校验上游版本**。你更新了上游文档却忘了重新 `fetch`，
`build` 出来的就是旧语料，而 `manifest.json` 里 `commit` 为空、`pinned` 为 false
（本项目当前正是这个状态）。**旧语料不是错误，但它必须被知道。**

## 7. 自检

**任务**：用两份报告证明"四类 chunk 都在、且白名单有覆盖自检"。

```bash
python -m maixrag --config configs/l2_hybrid.yaml corpus build
python -c "from pathlib import Path;print(Path('corpus/reports/stats.md').read_text(encoding='utf-8')[:400]);print('---');print(Path('corpus/reports/roster_gaps.md').read_text(encoding='utf-8'))"
```

**验收标准**（三条都要满足）：

1. `stats.md` 的"chunk 按类型"表四行齐全：signature 1898 / prose 1268 / code 605 / table 67；
2. `roster_gaps.md` **这个文件存在**（内容可以是"未发现缺口"），且你能说清
   "它不存在"与"它说没有缺口"为什么是两件事；
3. 你能指出四行里**哪一行归零对应哪一篇事故**。

- 验收：输出与期望一致，且能说出"`kind=signature` 为 0 但白名单 4868 条"意味着哪种失效
- 依据：[`postmortem/02`](../postmortem/02-有文档却召不回.md)

- 提示：改之前先回答"哪些 chunk 会消失"（看 3.4 的切分规则），再回答"分数会升还是降"

  concept 从 0.500 升到 0.688，而 code/table chunk 双双归零。若你预测"分数会降"，
  能说清是哪一步想错了吗？（提示：`kind` 不参与打分，但 code chunk 没了会改变
  BM25 的文档长度归一化与 token 池）
- 依据：[`concepts/02`](../concepts/02-语料与切分.md) 4.3 ·

- 提示：两种写法解析出的模块名要在同一条白名单里对得上——想清楚 `from maix import gpio`
