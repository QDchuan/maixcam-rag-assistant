# 05 · 评测

> 这一章要你**动手把量尺建起来**：给每道题标 ground-truth 依据片段，跑两条轴的报告，
> 再用覆盖率诊断确认那些数字**真的被测到了**。**这一步必须早于任何检索优化**。
> 前置：读 [concepts/07 评测：两条轴](../concepts/07-评测-两条轴.md)。

---

## 1. 一句话结论

**评测器不是验收工具，它是本项目唯一的量尺，必须第一批建成：**
每道题都标 `required_docs` / `required_spans`，报告按 `qtype` 分组，每条比率自带分母。

## 2. 为什么需要这一步

**没有评测，调优就是许愿**——RAG 没有编译错误，错答案和拒答在日志里长得一模一样。

两次真实事故都从"少一把尺子"开始：`signature` 召回 0.000 而语料里明明有 API 参考页，
只看总分 0.556 你会去换嵌入模型、调 top_k、加 rerank——**三个方向全错**（[事故 02](../postmortem/02-有文档却召不回.md)）；
4 轮预算的 agent 在 YOLO 题上失败，就被读成"agent 不适合"（[事故 06](../postmortem/06-预算与任务不匹配.md)）。
在 MaixCAM 上模型会把别的框架习惯带进来——`cv2.VideoCapture`、`RPi.GPIO`、`ultralytics.YOLO(`；
这类错误**不会让任何东西变红**，只会安静地变成一段看起来很专业的 Python。

## 3. 怎么做

### 3.1 建评测集：每道题都要有 ground-truth 依据片段

数据模型是 `maixrag/evaluation/harness.py` 的 `EvalItem`，题目在 `eval/datasets/seed.jsonl`（一行一题）。
下面一行摘自该文件：

```jsonc
{"qid":"q002","qtype":"signature",
 "question":"maix.camera.Camera 的构造函数有哪些参数？宽度和高度怎么指定？",
 "ground_truth":{"required_docs":["api/maix.camera"],
                 "required_spans":["width","height","buff_num"],
                 "must_contain":["width","height"],
                 "must_not_contain":["cv2.VideoCapture","camera.open_camera"]}}
```

`required_docs` + `required_spans` 只服务**检索轴**，缺了它只能测生成轴；
`must_contain` / `must_not_contain` 管生成轴；`qtype` 管分组。

**`must_not_contain` 是最有效的一类断言**：它不问答案对不对，只问那几样"绝对不该出现"的东西有没有出现——
`q002` 禁用 `cv2.VideoCapture`，`q005` 禁用 `ultralytics.YOLO(`。

### 3.2 四类 qtype：signature 与 example 必须占一半

设计稿 60 题：`concept` 20 / `signature` 15 / `example` 15 / `troubleshoot` 10。`signature` 与 `example`
合计占一半，**因为这两类是幻觉重灾区**（第一次踩的校验器误判就发生在 GPIO 那类代码上）。
实跑 18 题：8 / 4 / 4 / 2——配比对了但**样本量不够**，`signature` 只有 4 题，一题之差就是 25 pt。
所以分组数字**看方向，不看小数位**（[design/03 · 3.3](../design/03-评测与质量提升路线.md)）。

### 3.3 三类指标：能程序判的一律程序判

- **检索轴**：`Recall@K`（**主指标**）、`Hit Rate@K`、`MRR`、`Context Precision`——不调用模型，最便宜最稳。
- **生成轴**：引用精确率、引用召回率、符号级幻觉率、拒答是否正确，**全部程序能判**；`faithfulness` 是 `float | None`，judge 一栏写着 `(未使用)`。
- **运行指标**：现在只有 P50 延迟与错误率；token 与成本还没进 `Report`——**没有运行指标的消融表是不完整的**。

### 3.4 体检：先用 L0 基线筛掉送分题

```bash
python -m maixrag --config configs/l0_no_rag.yaml eval --level no_rag
```

不检索也能答对的题是噪音：它给每个配置都 +1，把真实差异稀释掉。按 `source` 分组也能看出送分题占比，
但**这一路体检还没做**——18 题的 `source` 全是 `real`。

## 4. 亲眼看一次

只测检索轴，不需要模型 key、不花钱（嵌入走本地 `bge-m3`）：

```bash
python -m maixrag --config configs/l2_hybrid.yaml eval --level rag --fake-chat
```

报告顶部会多一行 ⚠️（生成轴未被真实测量）。分组表才是重点——**`signature` 那一行不是 0.000**。
下面是本项目记录到的修复后分组（你自己的数字会随语料与检索配置移动）：

```
| qtype        | n | Recall@K |
| concept      | 8 | 0.500    |
| example      | 4 | 0.750    |
| signature    | 4 | 0.500    |
| troubleshoot | 2 | 1.000    |
```

再看覆盖率（不传参数时它挑**最新**的 `.json`，有多个结果时必须显式给路径）：

```bash
python scripts/inspect_eval.py "eval/results/rag_L1_rag[rrf_dense+bm25].json"
```

```
生成轴（注意看覆盖了多少题——0.000 可能只是「没测到」）
  **符号被检查到的题数  0/18  (0%)**
  ⚠️ 没有任何题目被检查到符号——幻觉率 0.000 不具参考意义
```

上面那份报告里"符号级幻觉率 0.000"和这里"0/18"是**同一次运行**的两个数字。

## 5. 证据

| 断言 | 值 | 性质 |
| --- | --- | --- |
| L1 链式检索轴（18 题 / Top-K=5） | Recall@K 0.611（[concepts/07](../concepts/07-评测-两条轴.md) 记录） | [本项目实测] |
| 只改语料（加 API chunk）前后 | signature 0.000→0.500 · example 0.250→0.750 · concept 0.625→0.500 · 总体 0.556→0.611 | [本项目实测] |
| 幻觉率的分母（L1 `.json`） | 报告写 `0.000`，items 里 `symbol_checked` 之和是 0 | [本项目实测] |
| agent 运行成本（18 题，[tutorial 00 · 4.4](../tutorial/00-主线导览.md)） | 88 次调用：search_docs 31 / lookup_api 25 / check_api_usage 21 / list_api 11，4.9 次/题 | [本项目实测] |

第二行是核心论据：**总体 +5.5 pt 底下是方向相反的两类变化**——只看总分是"小幅有效"，
按 `qtype` 看是"两类大幅改善、另一类被拖累"。

## 6. 失败的样子

**① 0.000 的幻觉率可能只是没测到东西**（真实事故：[事故 05](../postmortem/05-伪装成好消息的0.md)）

`hallucination_rate` 在 `symbol_checked == 0` 时返回 `0.0`，把"没有证据"和"证据表明没问题"编码成同一个数字。
更隐蔽的是：那个 0.000 是**在"有召回的题"上求的平均**（`Report._agg` 的 `with_ctx`），而真正被检查的符号数是 0。
核对方法：把 json 里 `items[*].generation.symbol_checked` 加起来。
连带坑：**`eval` 按 `{level}_{profile}.md` 覆盖同名文件**——跑一次 `--fake-chat` 就会覆盖真实模型的报告。

**② 送分题占比过高，评测就失去区分度**

一道不检索也能答对的题让**所有**配置一起涨分：分母变大、差值不变，差异被稀释到看不出来。
这正是 L0 基线存在的理由；而这一路体检本项目**还没做**（18 题 `source` 全是 `real`）。

**③ 评测集本身会坏：断言太弱或判错**

`must_contain` 是纯子串匹配，`q003` 的 `must_contain` 是 `["read"]`——`already read`、`read_frame` 里都含 `read`；
`q011` 的两个断言都是空数组，等于在生成轴上**免费通过**。另一头是**假阳性**：
[事故 03](../postmortem/03-校验器把正确代码判成幻觉.md) 里校验器把 `from maix import gpio` 产生的 `maix.gpio.GPIO`
判成幻觉，白名单从 2996 条补到 4868 条才修好。**误报率必须被量出来**，否则校验器会被忽略，真幻觉也一起被忽略。
另两项体检：**标注一致性**（两人独立标注 20%，一致率 <80% 修订规范）与不可判的断言改走 `reference_answer` + judge。

## 7. 自检

给你自己的语料写一道 `signature` 类题（照 `seed.jsonl` 里 q002），单独跑一次：

```bash
python -m maixrag --config configs/l2_hybrid.yaml eval --level rag --fake-chat --dataset eval/datasets/mine.jsonl
python scripts/inspect_eval.py "eval/results/rag_L1_rag[rrf_dense+bm25].json"
```

> ⚠️ 单题跑与全量跑的报告名**完全相同**（见 6 ①），先备份 `eval/results/`。

**验收**：① 逐题明细里这道题的 `召回率` 不是 `-`；② 把 `required_docs` 改错一个字符，
召回率必须掉到 **0**——没掉说明断言太松（`_doc_matches` 带前缀匹配），那道题测不出东西。

## 8. 课后习题

**A1（复现）** 跑一次只测检索轴的评测，抄下分组表（命令同第 4 节）。

- 提示：嵌入走本地 `bge-m3`，先 `ollama pull bge-m3`
- 验收：`signature` 行 **0.500**（不是 0.000）；总分与记录不一致时，能说出是语料还是检索配置变了
- 依据：[事故 02](../postmortem/02-有文档却召不回.md)

**A2（复现）** 指出报告里哪一栏的 0.000 **没有分母**，并说明为什么。

- 提示：看 `inspect_eval.py` 打出的"符号被检查到的题数"，再去 json 核对 `symbol_checked`
- 验收：能说清"幻觉率 0.000"与"触发禁止项比例 0.000"哪个没有分母
- 依据：[事故 05](../postmortem/05-伪装成好消息的0.md)

**C1（改造）** 给 `Report` 加一列"覆盖题数"，让报告里不再出现没有分母的比率。

- 提示：入口是 `maixrag/evaluation/harness.py` 的 `Report._agg` 与 `Report.to_markdown`；先想清楚每一列的分母是"全部题"还是"被测到的题"
- 验收：`符号级幻觉率` 那行带上 `0/18`（或 `18/18`），且 `recall`、`citation_precision`、`citation_recall`、`context_precision` 各自带上分母
- 依据：[事故 05 · C1](../postmortem/05-伪装成好消息的0.md)
