# 07 · 端到端

> 这一章要你动手做的事：把主分支 agent 完整装配起来跑一次，用真实模型走一道多跳问题、
> 读完它的轨迹，再用同一套评测器量它一次，最后自己判断"这个循环值不值"。
>
> 前置：[concepts/06 Agent 与链的区别](../concepts/06-Agent与链的区别.md)（决策由谁做）
> 与 [concepts/07 评测：两条轴](../concepts/07-评测-两条轴.md)（两把尺子）。
> 这一章不重复它们，只让你亲手跑出数字。

---

## 1. 一句话结论

**主分支 agent = 服务注册表 + 四个工具 + 拼装提示词 + 带预算的循环 + 沙盒策略。
它做到了链式做不到的多跳（YOLO 题上链式拒答、10 轮 agent 给出可运行代码并自检两次），
代价是 88 次工具调用（平均 4.9 次/题）；而检索轴那把尺子量不了它。**

## 2. 为什么需要这一步

前面每章都是**单点**（语料、检索、融合、生成、循环、权限）。单点跑通什么也证明不了——
本项目真实断掉的地方全是**接缝**：

- API 参考页产出了 1898 个符号，却没产出一个可检索 chunk：signature 类召回 **0.000**，
  而总分看起来正常（0.611）。见 [事故 02](../postmortem/02-有文档却召不回.md)。
- 18 道题的工具调用被统计成 **2 次**，因为统计读了一个每道题都被清空的数据源。
  见 [事故 04](../postmortem/04-被清空的统计.md)。
- 4 轮预算的 agent 在 YOLO 题上**输给链式**：它做了四步正确的多跳然后撞墙。
  见 [事故 06](../postmortem/06-预算与任务不匹配.md)。

这三件事在单点章节里都看不见，只在"把整条链路合起来跑一次、并且有基线可对比"时暴露。

## 3. 怎么做

### 3.1 先看清它被装成了什么

装配在 [`maixrag/agent/app.py`](../../maixrag/agent/app.py) 的 `build_agent()`，
五块机制挂成两个平面，判据只有一条——**这个服务会被作用域之外的消费者用到吗**：

| 平面 | 挂什么 | 判据 |
| --- | --- | --- |
| `infra`（全局） | `tools` 工具服务、`prompt` 装配器 | 提供工具的插件来自不同作用域 → 全局，且只挂一次 |
| `session`（会话） | 沙盒策略、四个 RAG 工具、循环+预算 | 只属于这一次会话 |

四个工具在 [`maixrag/agent/ragtools.py`](../../maixrag/agent/ragtools.py)，刻意分成两类：
`lookup_api` / `list_api` / `check_api_usage` 是**确定性查表**，只有 `search_docs` 是
**概率性检索**。提示词三段在 [`prompt.py`](../../maixrag/agent/prompt.py)，三条预算线在
[`loop.py`](../../maixrag/agent/loop.py)，路径范围检查在
[`sandbox.py`](../../maixrag/agent/sandbox.py)。

> **一个容易看错的地方**：`build_agent()` 打印 `提示词段落：persona, maixcam_rules`，
> 看起来少了 `tools_guide`——因为 `describe()` 在没有 facts 的情况下装配，而工具说明书
> 是动态段落，真正 `run()` 时由**当前注册的工具**渲染。说明书必须跟着实际工具走，
> 否则会出现"提示词里教了一个不存在的工具"。

### 3.2 不配密钥先跑通全流程

```bash
python -m maixrag --config configs/l2_hybrid.yaml agent \
  "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --max-turns 10 --fake-chat
```

`--fake-chat` 用假的决策模型（`maixrag/cli.py` 的 `_SimpleFake`）：先检索一次、再据结果作答。
它让装配、工具注册、循环、预算、轨迹打印在**无网络、无密钥**下走一遍，但**它不是真实模型，
它的调用次数不能用来回答"agent 值不值"。**

### 3.3 再用真实模型跑一道多跳问题

```bash
# .env 里填好 CHAT_API_KEY / CHAT_BASE_URL / CHAT_MODEL
python -m maixrag --config configs/l2_hybrid.yaml agent \
  "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --max-turns 10
```

它打印装配结果、**执行轨迹**（每轮的 decision 与 tool_result）、答案与依据。**轨迹是主角**。

### 3.4 用同一套评测器量它

```bash
python -m maixrag --config configs/l2_hybrid.yaml eval --level rag          # 链式基线
python -m maixrag --config configs/l2_hybrid.yaml agent-eval --max-turns 10 # agent 循环
python scripts/inspect_eval.py eval/results/agent_loop.json                # 看覆盖面
```

`agent-eval` 比 `eval` 多一段"agent 专属指标"：工具调用总数、失败数、被拒数、
**按工具分布**、平均每题工具调用；报告写进 `eval/results/agent_loop.md` 与 `.json`。

## 4. 亲眼看一次

**观察点一：轨迹里每一步是否合理。** 4 轮版本是这样断的（[事故 06](../postmortem/06-预算与任务不匹配.md)）：

```
第1轮  search_docs("YOLO 物体检测 例程", k=8)
第2轮  search_docs("YOLOv5 YOLOv8 YOLO11 物体检测 代码 yolo = YOLOv5")  ← 自己改写查询
第3轮  lookup_api("maix.nn.YOLOv5")                                    ← 切到确定性工具
第4轮  search_docs("yolov5.py 例程代码 detector = nn.YOLOv5 完整代码")  ← 用学到的类名重检索
       → 结束原因：轮次达到上限（4）
```

**要检查的具体现象**：第 4 轮的检索词 `nn.YOLOv5` 是**第 3 轮查签名才知道的**——
链里检索词只来自用户原始问题，没有第二次机会。10 轮版本接着第 5 轮
`check_api_usage(草稿代码…)`、第 6 轮 `lookup_api("maix.nn.YOLOv5.detect")`、
第 7 轮 `check_api_usage(修正后代码…)`、第 8 轮 `final`：**它自己校验了两次**。

**观察点二：成本指标里的平均工具调用数。** `agent-eval` 最后那段：

```
工具调用总数  88
其中失败      3
其中被拒      0
按工具分布    {'search_docs': 31, 'lookup_api': 25, 'check_api_usage': 21, 'list_api': 11}
平均每题工具调用  4.9 次/题
```

判据不是"4.9 好不好"，而是**对着预算看**：预算 10 轮、平均 4.9 次/题，说明对多数题目够用；
若平均调用数逼近上限，就是预算该调大的信号。

**观察点三：覆盖面。** `inspect_eval.py` 对 `agent_loop.json` 打出
`符号被检查到的题数 11/18 (61%)`——agent 报告里的"符号级幻觉率 0.000"
**只建立在 11 道题上**，而链式那份报告的覆盖面是 18/18。两者不是同一件事。

## 5. 证据

**定性对比（同一个 YOLO 问题、同一份语料、同一套工具）** `[本项目实测]`：

| | 链式（L1 基线） | agent（10 轮预算） |
| --- | --- | --- |
| 结果 | "资料中没有给出 YOLO 物体检测的完整代码，因此无法提供可直接运行的完整示例。" | 完整可运行代码，**自检两次** |
| 结构差异 | 一次检索机会，看见结果后不能改写查询 | 第 4 步把查签名学到的 `nn.YOLOv5` 反馈回检索 |

**两条轴与运行指标** `[本项目实测]`（18 题、Top-K=5；来源：
`eval/results/rag_L1_rag[rrf_dense+bm25].md`、`eval/results/agent_loop.md`；
agent 成本见上方观察点二）：

| 指标 | 链式 | agent |
| --- | --- | --- |
| Recall@K | 0.611 | 0.556 |
| MRR | 0.453 | 0.352 |
| 引用精确率 | 0.889 | 0.833 |
| 符号级幻觉率 | 0.000（覆盖面 18/18） | 0.000（覆盖面 **11/18**） |
| 拒答率 | 0.000 | 0.500 |
| P50 延迟 | 4,622 ms | 11 ms（命中磁盘缓存，见第 6 节） |

**结论只能这么写**：不是"agent 更好"，而是
**"agent 的能力上限更高，但它要求预算与任务深度匹配"**。

## 6. 失败的样子

**下面三条会让"agent 值不值"这个判断直接失效。**

### 失败一：检索轴的尺子量不了 agent

`Recall@K` 只看**前 5 个召回片段**。链式只有一次检索，这把尺子对它是完整的；
agent 是多次检索、**累积证据**的——正确文档出现在第 2、3 次检索里，指标只看第一次。

所以 `0.611 → 0.556` **不能读成"agent 检索更差"**，只能读成"这把尺子量不了它"。
想真正量 agent，需要"累积证据"口径的检索指标——**这是明确的待办，不是已解决的问题**。
入口是现成的：`RagTools.all_hits` 已按连续编号累积了整个会话的片段，
缺的只是"在累积集合上算召回"的口径定义。

> **这个局限本身就是教学点**：当一把尺子量不出差异时，**先怀疑尺子，再怀疑被测对象**。
> 两者长得一模一样，都表现为"新方案的数字更差"。

### 失败二：预算与任务深度不匹配时，agent 会不如链式

同一道 YOLO 题，4 轮预算的 agent 输出"未能完成回答，原因是：轮次达到上限（4）"，
而链式至少给了一个明确答案。**用配置错的方案去比基准，得到的结论不是
"这个方案不好"，而是"这个方案在配置错的时候不好"。**

### 失败三：0.000 的分母只有 11/18

agent 的"符号级幻觉率 0.000"和链式一样漂亮，但覆盖率只有 11/18：
**7 道题的回答里没有出现任何可校验的 maix 符号**，它们对这个 0.000 没有贡献。
0.000 永远有两种含义——真的很好，或几乎没测到东西（[事故 05](../postmortem/05-伪装成好消息的0.md)）。
顺手核一下：拒答率 0.500 意味着 18 题里 9 题被判定为拒答/降级。

另一条只影响读数的坑：**时间类指标在这份报告里不可比。** agent 的 P50 是 11 ms、
链式是 4,622 ms，因为模型输出落在 `indexes/cache/chat` 的磁盘缓存里，重跑没打网络。
要拿时间做结论，必须先清缓存并说明这一点。

## 7. 自检

**任务**：跑一次 `agent-eval`，回答"这次跑里 agent 的自检发生在哪几轮、覆盖了哪几道题"。

**验收**（三条都要满足）：

1. 说出 `check_api_usage` 被调用的次数，以及它占全部工具调用的比例；
2. 用 `python scripts/inspect_eval.py eval/results/agent_loop.json` 说出
   "符号被检查到的题数"是几分之几，并解释这个分母为什么必须出现在报告里；
3. 说出为什么"agent 的 Recall@K 比链式低"不等于"agent 检索更差"。

## 8. 课后习题

**A1（复现）** 用 4 轮和 10 轮各跑一次同一道 YOLO 题，对比轨迹。

- 提示：看结束时打印的 `结束原因` 与 `消耗`；4 轮那次会打印降级答案
- 验收：能指出 10 轮版本里**链式架构做不到**的那一步，以及它用到了第 3 轮的哪个信息
- 依据：[`postmortem/06`](../postmortem/06-预算与任务不匹配.md)、
  [`concepts/06`](../concepts/06-Agent与链的区别.md)

```bash
python -m maixrag --config configs/l2_hybrid.yaml agent \
  "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --max-turns 4
```

**A2（复现）** 跑一次 `agent-eval --max-turns 10`，核对平均每题工具调用数是否等于
`工具调用总数 / 18`。

- 验收：算出的值与打印值一致（一位小数）；能说出这个统计为什么不能读 `tools.history`
- 依据：[`postmortem/04`](../postmortem/04-被清空的统计.md)

**B1（改造）** 把预算压到 `--max-turns 2`，**先写下预测**（会不会拒答？平均调用数多少？），
再跑 `agent-eval` 验证。

- 验收：预测与实测方向一致；不一致时能解释哪一步想错了
- 依据：[`postmortem/06`](../postmortem/06-预算与任务不匹配.md)

**C1（改造）** 设计一个"**累积证据**"口径的检索指标，并说清它和 `Recall@K` 的差别。

- 提示：`RagTools.all_hits` 已把整次会话召回的片段按连续编号累积；这个指标要回答
  "**在 agent 花掉的全部检索预算里，该召回的内容出现了没有**"，而不是
  "第一次检索的前 5 名里有没有"。两个口径至少两处不同：分母是什么、编号是否跨轮次
- 验收：先预测 agent 与链式在这个指标上的差值方向（谁高、为什么），再与实际值对比；
  不一致时能说出哪一步想错了
- 依据：[`concepts/07`](../concepts/07-评测-两条轴.md) 的"误解四"、
  [`concepts/06`](../concepts/06-Agent与链的区别.md) 的"误解四"、
  [`maixrag/agent/ragtools.py`](../../maixrag/agent/ragtools.py) 的 `search_docs`

> 问答题见 [`../exercises/concepts/06-Agent与链的区别.md`](../exercises/concepts/06-Agent与链的区别.md)
