# 06 · Agent 五块机制

> 这一章要你**动手把自己仿写的 agent 基座跑起来**：五块机制各看一个现场
> （三个演示脚本 + 一次真实轨迹），看清"能力怎么接进来、模型怎么知道有什么能力、
> 提示词怎么拼、它怎么停下来、它不能做什么"。
>
> 前置：先读 [concepts 06 Agent 与链的区别](../concepts/06-Agent与链的区别.md)
> 建立"决策由谁做"这个心智模型，本章不再重复推导。
> 权限那一块另配 [concepts 08 权限与沙盒](../concepts/08-权限与沙盒.md)。

---

## 1. 一句话结论

**主分支的五块机制，每一块都对应 agent 相对链多出来的一个运行时问题**：
能力要能被替换（注册表）、能力要能被模型看见（工具）、提示词要能被多方贡献（装配）、
循环要能停下来（预算）、循环要能被拒绝（沙盒）。

五块里没有一块是"模型更聪明"能替代的——这正是本章要你亲手验证的事。

## 2. 为什么需要这一步

先看没有它会怎样，全部是本项目真实撞到的：

| 没有这一块 | 本项目里真实发生的事 |
| --- | --- |
| 服务注册表 | 检索服务被"每个会话各挂一份"，两份索引、两次构建、语料版本还可能不一致 |
| 工具协议 | 模型不知道 `lookup_api` 存在，只能一遍遍 `search_docs`，多跳做不起来 |
| 提示词装配 | 防幻觉那五条纪律和工具说明书混成一个常量字符串，改一段不知道会崩哪一段 |
| 循环与预算 | 预算 4 轮时 agent 在 YOLO 题上**输给链式**（[事故 06](../postmortem/06-预算与任务不匹配.md)） |
| 权限沙盒 | 越界写入会真的发生；而"拦住了"不等于"拦对了" |

第三行值得多看一眼：本项目的主问题是 **`MaixPy 里怎么做 YOLO 物体检测？给出完整例程`**。
链式只有一次检索机会，看不见结果之后不能改检索词，也没有确定性工具可切。
**这不是配置问题，是结构性缺失**——五块机制就是补这个结构。

## 3. 怎么做

### 3.1 服务注册表：按名字，不靠 import

能力**按名字注册、按名字解析**，提供方与消费方彼此不知道对方是谁。
换检索实现不需要改任何 import 它的地方；想知道"谁提供了什么、在哪个平面"，一条命令能打出来。

两个平面的判断只有一句话：

> **这个服务会被作用域之外的消费者用到吗？**
> 会 → 全局平面，且**只创建一个提供方**
> 不会 → 隔离域

本项目实例：检索服务、API 符号白名单是**全局**（前端、评测、多个会话都在读它）；
某个 agent 自己的工作流引擎是**隔离域**。
代码：`maixrag/agent/registry.py`。

### 3.2 工具：描述即提示词

三条纪律，缺一条就有实际后果：

1. **描述即提示词。** 模型选哪个工具完全靠读 `description`，
   所以空描述的工具被**当场拒绝注册**——没描述的工具体等于不存在。
2. **错误是结果，不是异常。** `ok=False` 会作为观察结果回灌给模型；
   模型看到"缺少必填参数"会自己改，循环崩了就什么都没了。
3. **权限声明在工具上。** 每个工具声明 `requires`（`fs:write` / `exec` / `net`）与
   `path_params`（哪些参数是路径），权限系统因此有明确检查点。

管线顺序是**存在性 → 参数 → 权限 → 执行**，不能反：
反了会让一次"参数写错的调用"也弹审批窗口，白白打扰人一次。代码：`maixrag/agent/tools.py`。

### 3.3 提示词装配：装配器不知道任何内容

装配器只做三件事：按 `order` 排序、拼接、记录每段的来源与长度。
**它不知道 persona 是什么，也不知道工具说明书里有几个工具。**

| | 静态段落 `section` | 动态上下文 `context` |
| --- | --- | --- |
| 内容 | 人设、回答纪律 | 工具说明书、检索到的资料 |
| 变化 | 几乎不变 | 每轮都变 |
| 放哪 | 系统提示的稳定前缀 | 跟随用户消息 |

混在一起等于每轮都让提示词缓存失效。本项目没实现缓存，但这个划分是"该放哪"的判断依据。
代码：`maixrag/agent/prompt.py`（默认三段在 `make_maixcam_prompt`）。

### 3.4 循环与预算：它怎么停下来

三条线各防一种失效，只设一条必漏（只有轮次上限时，一轮里可以调一百次工具）：

| 预算 | 防什么 | 出问题时的样子 |
| --- | --- | --- |
| 轮次 | 模型反复横跳 | "我再查一次"循环二十遍 |
| 工具调用次数 | 单轮内疯狂并发 | 一次读两百个文件 |
| token | 上下文无限膨胀 | 每轮把全部历史塞回去 |

失败恢复三种，**都是刻意的**：

| 情形 | 处理 | 为什么 |
| --- | --- | --- |
| 工具失败 | 错误回灌，**不终止** | 终止的话，一次参数写错就毁掉整个任务 |
| 连续同类失败 | 提前终止（`max_repeated_errors`） | 防"在修不好的错上把预算烧光"；但错误类型在变时不算卡住 |
| 预算耗尽 | **优雅降级** | 静默失败会伪装成成功 |

代码：`maixrag/agent/loop.py`（`Budget` / `AgentLoop`）。

### 3.5 权限沙盒：三层边界与失败关闭

| 层 | 问题 | 缺了它会怎样 |
| --- | --- | --- |
| 能力边界 | 能做哪类事 | 工具直接调系统调用，绕开一切控制 |
| 范围边界 | 能做到多大 | 能"写文件"但不知道能写到哪 |
| 审批边界 | 什么必须问人 | 危险操作被静默放行 |

一条压倒性的原则：**失败关闭**。没有审批人时拒绝、路径解析失败时拒绝、
路径参数不是字符串时拒绝。另一条同样重要：**拦截越界不能靠字符串前缀**——
先 `resolve()` 规范化并解析符号链接，再用 `relative_to` 做包含判断。
代码：`maixrag/agent/sandbox.py`。

## 4. 亲眼看一次

三个脚本各跑一次（现场一~三），再用一条命令看五块机制在线上的样子（现场四~五）。
前三者**不需要任何 API key、不需要索引、不需要嵌入模型**。

```bash
python scripts/demo_planes.py     # 架构错：把该共享的服务放进隔离域 / 每个会话各挂一份
python scripts/demo_budget.py     # 工程错：不设预算的 agent 停不下来
python scripts/demo_sandbox.py    # 安全错：越界写入真的发生，且"拦住了≠拦对了"
```

Windows 上把 `python` 换成 `.venv\Scripts\python.exe`（Linux/macOS 用 `.venv/bin/python`）。

**`demo_planes.py` 的关键观察点：场景二那行报错。**
它打印的是 `全局服务 'maixcamRag' 已被 'maixcam-rag' 注册，'maixcam-rag' 无法再注册。`
紧接着一句是重点——**`这不是 bug，是机制在拦住一个设计错误`**。
然后再看场景三末尾的分组表，`全局服务（所有作用域可见）` 下只有一条 `maixcamRag`，
而 `隔离域内的服务（仅域内可见）` 是 `（无）`：**两个会话共用同一份**。
把场景一的表和场景三的表对照，就是"两份索引"与"一份索引"的区别。

**`demo_budget.py` 的关键观察点：场景一结束时的 `结束原因：budget` 和 `消耗`。**
它打印 `{'turns': '30/30', 'tool_calls': '30/9999', 'tokens': '0/1000000000'}`，
而**30 次工具调用每一次都是"成功"**（`search_docs` 返回"找到 0 个片段"）。
没有报错、没有异常，只是没有进展——这就是本项目说的"失败是无声的"。
再对比场景二：同样撞上限，但答案是"未能完成回答，原因是：轮次达到上限（4）"
加上"已完成的部分"，用户知道自己拿到的是半成品。

**`demo_sandbox.py` 的关键观察点：场景三那张两列对比表。**
`兄弟前缀目录` 与 `.. 向上穿越` 两行，在列 `字符串前缀判断` 下都是 `放行 ❌`，
在列 `规范化+解析链接` 下都是 `拦住 ✅`。
**同一批路径，两种判定给出相反结论——"拦住了"和"拦对了"是两回事。**
场景一还打印了 `实际写入的位置`，那是工作区之外的临时目录：在没有策略时，越界写入真的发生了。
若本机不允许创建符号链接（Windows 常见），第三行会显示"该用例由单元测试覆盖"，
这是**显式跳过**，不是通过。

**第四个现场：五块机制在线上的样子。** 它不联网也能跑
（前置：按 [00 主线导览 · 0](./00-主线导览.md) 建好语料与索引）：

```bash
python -m maixrag --config configs/l2_hybrid.yaml agent "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --fake-chat --max-turns 3
```

输出里能看到本章的四件事同时出现：`可用工具` 一节列出四个工具的名字、描述与能力
（`[pure]`，这就是 3.2 说的"模型看到的暴露面"）；`提示词段落：persona, maixcam_rules`
（装配的静态前缀）；`【执行轨迹】` 逐轮打印决策；末尾
`结束原因：final   消耗：{'turns': '2/3', 'tool_calls': '1/6', 'tokens': '0/60000'}`
（预算记账）。
**注意 `tokens` 是 `0`**——`--fake-chat` 的假模型不报 token，所以第三条预算线在这个演示里
量不到东西；要看 token 记账得看 `tests/test_agent_loop.py` 里的确定性断言。

**第五个现场：一把量不了 agent 的尺子。** 同一道命令换成批量评测：

```bash
python -m maixrag --config configs/l2_hybrid.yaml agent-eval --max-turns 10 --fake-chat
```

本次复跑它是 `Recall@K = 0.028`、`工具调用总数 1`、`平均每题工具调用 0.1 次/题`，
报告开头还有两行警告：`⚠️ 决策用的是假模型：只验证流程，不代表真实表现`。
**别把这个 0.028 读成"agent 很差"**——它读作"假模型的评测没有意义"。
（同配置换真实模型，文档记录是 0.556；链式本次复跑是 0.694。
这两个数不是同一时刻量的，不要直接相减——详见 6.4。）

## 6. 失败的样子

### 6.1 架构错：把"共享一份"做成了"每份一个"

隔离域不是"更安全的选择"，它是**有代价的选择**。
场景一里两个会话各加载一份索引：一份内存变两份、一次构建变两次，
而且**语料版本可能不一致——同一句话问两次，答案不同**。
反过来把只属于一次挂载的东西放进全局，就是场景二那种撞名失败。
判断规则本身也可能被误用：**有没有外部消费者，往往从插件名字看不出来**，
所以要看谁在引用它，而不是它叫什么。

### 6.2 工程错：预算给少和给多是两个相反的坑

必须同时记住两件事，否则会各自走偏：

- **预算太小**：agent 做不完多跳，输出"我没做完"——这是**显式失败**，可诊断；
- **等于没设**：每次都"成功"、只是没有进展——这是**无声失败**，最危险。

而 `demo_budget.py` 场景一**不是**在证明"预算该设小"，恰恰相反：
它演示的是"上限大得等于没有约束"。
所以"默认值保守"不等于"该用的时候要用小值"——**预算是任务与成本之间的谈判，不是安全阀**。

### 6.3 安全错：权限默认值是安全漏洞

`SandboxPolicy` 的默认是"什么都不能做"，`ToolRegistry` 的默认权限却是 `AllowAll`（放行一切）。
这个不一致是**刻意的教学材料**：`AllowAll` 是所有 AI 应用里最危险的一行代码，
它让"忘了配权限"从配置疏漏变成安全漏洞。
三种错误的性质不同，不能混为一谈：

| 类别 | 症状 | 修法 |
| --- | --- | --- |
| **架构错**（`demo_planes.py`） | 能力放错平面 → 浪费、不一致、或挂载失败 | 重新判断"谁在消费它" |
| **工程错**（`demo_budget.py`） | 跑飞，而且**没有报错** | 补预算 + 让消耗可观察 |
| **安全错**（`demo_sandbox.py`） | 越界写入真的发生；前缀判断放行绕过 | 换判定方法（`resolve` + `relative_to`）+ 失败关闭 |

### 6.4 两个会让你误判的地方

1. **`--fake-chat` 的轨迹量不了循环质量，agent-eval 的数字更量不了。**
   假模型永远只走 `search_docs → final` 一两步，真正的多跳（改写查询、切确定性工具、
   写完自检）只有真实对话模型才会出现。这不是推论——本次复跑里
   `agent-eval --fake-chat` 打出的 `Recall@K = 0.028`、工具调用总数 **1**，
   而报告自己就带了两行警告：`⚠️ 决策用的是假模型：只验证流程，不代表真实表现`。
   **同一个配置换真实模型，文档记录是 0.556（不是 0.028）。**
   token 那一格里的 `0` 也是同一个原因：假模型不报 token。
2. **agent 的检索轴数字比链式差，不代表 agent 更差。**
   Recall@K 那把尺子只看第一次检索的 Top-5，而 agent 的正确文档出现在第 2、3 次检索里——
   **它量不了 agent**。当一把尺子量不出差异时，先怀疑尺子。
   另外注意：链式本次复跑是 **0.694**，而文档里 agent 的 0.556 来自更早的冻结版本，
   **两个数不是同一时刻量的，不要直接相减**。详见 [tutorial 00 · 4.3](./00-主线导览.md)。

## 7. 自检

**可做的小任务**：新建 `scripts/check_planet.py`，用 `maixrag.agent.registry`
搭两个作用域 `session-1` / `session-2`，各挂一个消费 `maixcamRag` 的插件，
但**故意把这个服务挂在会话作用域里而不是基础设施作用域里**（`isolate=False`）。
运行它，你会看到 `demo_planes.py` 场景二那个撞名失败。

**验收标准**（两条都要满足）：

- 脚本能跑出非零退出或明确的错误信息，且错误里包含**是哪个服务、被谁注册**；
- 然后你能**只改挂载位置**（把提供方移到 `reg.scope("infra")` 里，只挂一次）
  让它跑通，并说出改的是哪一个平面、为什么。

再加一条读代码的验收：不读 `registry.py`，先回答
① `Context.get(name)` 与 `Context.require(name)` 的分工是什么、各自适合什么依赖；
② `ToolRegistry.execute()` 的四步顺序是哪四步，把权限检查提到参数校验之前会有什么后果。
然后去代码里核对。

## 8. 课后习题

**A1（复现）** 跑三个演示脚本，各找出一个**只靠读文字描述看不出来**的现象。

- 提示：场景里的数字（30/30、`放行 ❌`、`（无）`）比解释文字可信
- 验收：三个现象分别对应哪一块机制，且能说出它属于架构/工程/安全哪一类错
- 依据：[concepts 06](../concepts/06-Agent与链的区别.md)、[事故 06](../postmortem/06-预算与任务不匹配.md)

**A2（复现）** 用 `--fake-chat --max-turns 1` 跑那道 YOLO 题，把输出里的
`结束原因` 与 `【答案】` 抄下来，和 `--max-turns 3` 的输出对比。

```bash
python -m maixrag --config configs/l2_hybrid.yaml agent "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --fake-chat --max-turns 1
```

- 提示：1 轮预算下模型第 1 轮就调工具，第 2 轮进来时已经耗尽
- 验收：输出里出现"未能完成回答"和具体的耗尽原因（不是空的答案），
  且你能指出这是 `_degrade` 而不是异常
- 依据：[事故 06](../postmortem/06-预算与任务不匹配.md)、`maixrag/agent/loop.py`

**C1（改造）** 把预算改成 2 轮，复现"agent 比链式还差"。

```bash
# agent 一侧：2 轮预算
python -m maixrag --config configs/l2_hybrid.yaml agent "MaixPy 里怎么做 YOLO 物体检测？给出完整例程" --max-turns 2
# 链式一侧：同一道题（需可用对话模型 key）
python -m maixrag --config configs/l2_hybrid.yaml ask "MaixPy 里怎么做 YOLO 物体检测？给出完整例程"
```

- 提示：先写下你的预测——两边各会给出什么**形态**的答案；
  注意"没答出来"和"明确拒答"不是同一件事，而"比链式还差"说的是前者
- 验收：预测与实测一致；若不一致，能说出你是把"预算不够"看成了"方法不行"，
  还是反过来。判据是**看轨迹里每一步是否合理**，不是看最终指标
- 注意：用 `--fake-chat` 跑不出这个现象——假模型第 1 轮就 `search_docs`、
  第 2 轮就 `final`，2 轮对它够用（见 6.4）。要复现事故现场需要真实对话模型
- 依据：[事故 06](../postmortem/06-预算与任务不匹配.md)（含 4 轮 vs 10 轮的完整轨迹）

**C2（改造）** 给 `SandboxPolicy` 加一行"写操作需要审批"，观察越界写入从
"直接拒绝"变成"等待审批"；然后把 `approver` 换成 `DenyApprovalUnavailable`，再观察一次。

- 提示：注意 `needs_approval` 与 `allowed` 是两个集合，`check()` 里它们先查哪个；
  默认的审批通道本来就是"没人可问就拒绝"，所以第二次观察的重点是**它没变**
- 验收：两次运行的判定不同（一次"需审批"、一次"直接拒绝"），
  且你能说清"没有审批人时拒绝"为什么必须是这样——换成"没人问就放行"会作废哪一层
- 依据：[concepts 08 权限与沙盒](../concepts/08-权限与沙盒.md)、`maixrag/agent/sandbox.py`
