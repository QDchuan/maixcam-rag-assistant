# 01 · 失败是什么样的

> 这一章要你动手做的事：**在没有 MaixPy 资料的前提下，把四个 MaixCAM 的真实问题问一遍通用大模型，
> 把它编 API 的方式归到四类里去**——后面每一章的方案，都对应这里看到的某一种失败。
>
> 前置：[concepts/00 为什么需要 RAG](../concepts/00-为什么需要RAG.md) ·
> [concepts/05 生成与忠实性](../concepts/05-生成与忠实性.md)

---

## 1. 一句话结论

**不给资料时，通用大模型写 MaixPy 不会说"我不知道"，它会给你一段读起来通顺、格式专业的代码。**
它错得**有规律**，只有四种形态：编造不存在的方法 / 串 OpenCV / 串树莓派 / 串 K210 时代的 MaixPy v1。
所以失败不是"答得差"，而是**答得很像真的**——肉眼看不出来，必须用程序化的尺子量。

## 2. 为什么需要这一步

不先看这一眼，后面每个环节都会被同一个错觉骗过去：以为换更大的模型就行（知识不在权重里，见
[concepts/00](../concepts/00-为什么需要RAG.md) 误解一）；以为提示词里写"不要编造"就够（劝告没有
强制力）；以为答案通顺就是对的（报错发生在 MaixVision 里，不在对话里）。

本项目把"见过失败"做成了可归档的事：`eval/datasets/seed.jsonl` 每道题的 `must_not_contain` 字段
装的就是**曾经真的出现过**的错法——18 道题里 16 道非空 [本项目实测]。**防幻觉的能力就是从这一章的
动作里长出来的**：先记录失败，再把失败变成断言。

## 3. 怎么做

**动作一（手工）。** 打开任意通用大模型，**不附 MaixPy 资料、不开联网检索**，把 4.1 的四句话粘进去，
抄下它写出的每个 API 名。

**动作二：复现"无资料"这条基线。**

```bash
# venv 见 tutorial 00；填了 .env 的 CHAT_API_KEY 就是真实模型
python -m maixrag --config configs/l0_no_rag.yaml ask "MaixCAM 上怎么把一张图放大两倍？" --level no_rag
```

`--level no_rag` 是 L0 基线：不检索、不给资料，直接问模型——动作一被自动化后就是这个形态。

**动作三：用确定性假模型复现同一行为（不要 key、不联网）——在动作二的命令前加一行。**

```bash
$env:CHAT_MODEL = "fake"     # Windows PowerShell；bash 下等价 —— 让 make_chat 返回 FakeChat
```

`FakeChat`（`maixrag/providers.py`）是一个**刻意会犯错的**假对话客户端：没有上下文时输出一个编造的
API，有上下文时只从资料里抄一个符号。它和"假嵌入"一样，是为了不把读者的第一步卡在 API Key 上。

> **别改用 `--fake`**：它走 `make_profile`，换的是 `NoopChat`（什么都不答），答案是空的。
> "离线能跑通"和"能看到幻觉"是两个开关。

## 4. 亲眼看一次

### 4.1 四句话，直接粘贴

| # | 粘贴这一句 | 观察的形态 | 对应的真实禁项 |
| --- | --- | --- | --- |
| 1 | `MaixCAM 上怎么把一张图放大两倍？给出完整的 MaixPy 代码。` | 编造不存在的方法 | `maix.image.Image.super_resolve`；`camera.open_camera`、`read_frame`、`enumerate_cameras` |
| 2 | `MaixCAM 上怎么读取摄像头、逐帧取图？` | 串 OpenCV | `cv2.VideoCapture`、`cv2.cvtColor`、`cv2.findContours`、`cv2.imread` |
| 3 | `MaixCAM 的 GPIO 怎么点灯？` | 串树莓派 | `RPi.GPIO`、`wiringpi`、`picamera`、`pyaudio`、`serial.Serial` |
| 4 | `MaixCAM 上怎么初始化摄像头？` | 串 K210 时代 MaixPy v1 | `sensor.*`（`maixrag/agent/prompt.py` 把它列为三大串味来源之一） |

读法：不要只看答得对不对，看它**有没有一句"我不确定"**——四段代码都有 import、有参数名。

### 4.2 用假模型把同一件事变成可复现的

```bash
python -c "import json; from maixrag.providers import FakeChat; print(json.loads(FakeChat().complete('system', 'MaixCAM 上怎么把一张图放大两倍？', json_mode=True))['answer'])"
```

本机实测输出：

````
可以使用 `maix.image.Image.super_resolve()` 来提升分辨率。

```python
img = image.Image()
img = img.super_resolve(scale=2)
```
````

**这就是"失败的样子"的标准样本**：限定名、可执行代码、参数 `scale=2`、JSON 返回，全都像模像样——
唯一的问题是 **`super_resolve` 不存在**。验证（输出 `[]`）：

```bash
python -c "print([l for l in open('corpus/processed/api_roster.txt',encoding='utf-8') if l.startswith('maix.image.Image.super_resolve')])"
```

必须用 `startswith`，理由见第 6 节第三点。

### 4.3 用项目自己的校验器看另外三种形态

```bash
python scripts/check_symbols_demo.py
```

本机实测输出：7 条用例全部 ✅；白名单条数 4868；三条幻觉用例分别抓到
`maix.camera.Camera.super_zoom`（编造方法）、`maix.camera.VideoCapture`（照搬 OpenCV）、
`maix.camera.PiCamera`（照搬树莓派）。

> ⚠️ **中文 Windows 控制台可能直接报错**：这个脚本没有自己重设输出编码，
> 在 GBK 代码页下打印 `✅` 会抛
> `UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`（退出码 1）。
> 先设一次 `$env:PYTHONIOENCODING = "utf-8"`（或 `chcp 65001`）再跑，就能看到全部 ✅。
> **这是控制台编码问题，不是校验器的问题**——别把它当成"校验器坏了"。

注意名字变成了 `maix.camera.VideoCapture`：**"串了 OpenCV"变成了一次确定性的查表失败。**

## 5. 证据

| 事实 | 内容 | 性质 |
| --- | --- | --- |
| 语料与白名单 | 119 篇中文教程 + 56 页 API 参考；3838 chunk（605 代码 / 67 表格 / 1898 signature）；白名单 1898 个符号 / 4868 条 | [本项目实测] |
| 评测集禁项 | 18 题中 16 题带 `must_not_contain`，覆盖编造方法 / OpenCV / 树莓派三类 | [本项目实测，数自 `eval/datasets/seed.jsonl`] |
| 真实模型侧 | L1 链式在 YOLO 题上拒答，并声明"不能凭 OpenCV、K210 时代 MaixPy v1 的习惯推测 API" | [本项目实测，见 [tutorial 00](./00-主线导览.md) 4.1] |

**K210 那一类没进评测集**——只写在提示词纪律里。这是本章证据的缺口：**写了纪律 ≠ 测了纪律。**

## 6. 失败的样子

**一、你观察到的可能不是你要测的东西。** 模型带联网检索就会自己去搜（你测到的是"别人家的 RAG"）；
采样与版本会让两次答案不同（"亲眼看到"只能建立直觉、**不能当证据**）。本项目的处理是把它固化：
确定性的 `FakeChat` + 评测集里的 `must_not_contain` 断言。

**二、通顺本身就是难点。** 模型不会说"我不知道"，所以**肉眼检查会漏，而且漏得有系统性**：你得先懂
MaixPy 才看得出哪里错，而"没看出错"和"没错"在感觉上完全一样。

**三、白名单也会骗你，后果更严重。** 本项目把**正确的** `gpio.GPIO`、`gpio.Mode.OUT` 判成过幻觉
（文档路径 `maix.peripheral.gpio` ≠ 用户实际写的 `maix.gpio`）。误报会训练人忽略警告，**于是真幻觉
也一起被忽略**（[事故 03](../postmortem/03-校验器把正确代码判成幻觉.md)）。**断言写宽了会误伤，
写短了会漏。**

**四、写了纪律，不等于测到了。** `sensor.*` 只在 `maixrag/agent/prompt.py` 里被点名，评测集里没有
对应禁项。按本项目的纪律，**没有被断言覆盖的知识点等于没有被测过**。

## 7. 自检

**任务**：给四类形态各写一条 `must_not_contain` 断言，并把 4.2 那条 `startswith` 检查里的符号换成你
写下的四个限定名，逐个跑。

**验收标准**：① 四条各自打印 `[]`；② 能说出为什么至少一条不能用短子串写（提示：白名单里有一个
合法符号以 `cv2` 开头）；③ 能指出哪一条不是本项目已有的断言、为什么还没有。

## 8. 课后习题

**A1（复现）** 跑 4.2 的两条命令：先让 `FakeChat` 输出，再查白名单。

- 提示：第二条必须用 `startswith`，不要用 `in`
- 验收：第一条打印出含 `super_resolve` 的代码块，第二条打印 `[]`
- 依据：[`concepts/05`](../concepts/05-生成与忠实性.md) · [`maixrag/providers.py`](../../maixrag/providers.py)

**A2（复现）** 跑 `python scripts/check_symbols_demo.py`，把 7 条用例分成"应放行 / 应抓到"两组。

- 提示：第 7 条"无关代码"打印「检查 0 个符号」，它依然算通过——为什么？
- 验收：7 条全部 ✅，白名单条数为 4868
- 依据：[`postmortem/03`](../postmortem/03-校验器把正确代码判成幻觉.md)

**C1（改造）** 关掉 `hallucinate_on_miss` 再跑一次，**先写下预测**：

```bash
python -c "import json; from maixrag.providers import FakeChat; print(json.loads(FakeChat(hallucinate_on_miss=False).complete('system', 'MaixCAM 上怎么把一张图放大两倍？', json_mode=True))['answer'])"
```

- 提示：想清楚"会犯错的假模型"在教学项目里是干什么用的——它不是偷懒的替代品
- 验收：预测与实测一致；不一致时能说出漏考虑了哪一步，并解释关掉后**校验器那一级会失去什么**
- 依据：[`maixrag/providers.py`](../../maixrag/providers.py) · [`concepts/05`](../concepts/05-生成与忠实性.md) 误解一
