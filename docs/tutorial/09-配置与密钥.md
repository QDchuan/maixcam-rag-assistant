# 09 · 配置与密钥

> 这一章要你动手做的事：把模型端点配起来，并且**说清密钥存在哪、
> 为什么存在那、以及怎么确认它没有泄漏**。配完能跑 `demo`，就算过。
>
> 前置：[tutorial 07 端到端](./07-端到端.md)（装配与评测）、
> [concepts 08 权限与沙盒](../concepts/08-权限与沙盒.md)（边界思维）。
> 这一章不重复它们，只处理"怎么让别的东西跟这个项目接上"。

---

## 1. 一句话结论

**配置有两条路，随便走哪条：**

```bash
python -m maixrag setup          # ① 对话式向导：问你几个问题，当场验证连通，再写盘
```

或者

```bash
# ② 直接编辑文件，不看任何向导
.env                             # 密钥与端点
configs/l2_hybrid.yaml           # 检索与生成的行为
```

**向导只是"降低第一次的门槛"，它不掌握任何独家知识。**
所有值都能直接写进文件——而且**出问题时你应该去看文件**，
因为藏起来的配置在坏掉的时候最难查。

## 2. 为什么需要这一步

前面八章都在讲系统内部怎么运转。但一个系统真正的第一道坎在**更外面**：
它得先能连上模型。

而这件事在真实项目里造成的流失，比任何算法问题都多：

| 现象 | 真实原因 |
| --- | --- |
| "跑不起来" | 不知道要配 `.env` |
| "报未配置 API Key" | 配了，但变量名拼错 / 放错文件 |
| "配好了但检索是随机的" | 嵌入端点不通，静默退回了假嵌入 |
| **"密钥泄露了"** | 密钥写进了 `configs/*.yaml`，然后被提交 |

最后一条是这一章真正的主角。**配不好只是跑不起来；配错了位置是要吊销密钥的。**

## 3. 怎么做

### 3.1 三个文件，各管一件事

| 文件 | 放什么 | 会不会被提交 |
| --- | --- | --- |
| **`.env`** | **密钥**、端点地址、模型名 | ❌ 已被 `.gitignore` 排除 |
| `configs/*.yaml` | 实验配置：检索器、切分策略、`top_k`… | ✅ 会提交（**所以绝不能放密钥**） |
| `maixrag/config.py` | 代码里的默认值 | ✅ 会提交（不含任何真实密钥） |

**判据只有一条：这个值是不是秘密？**
是秘密 → 只能进 `.env`；不是秘密 → 放 yaml，因为它会进版本库、会被评审、会被复现。

> 一个常见的错误写法是在 yaml 里写
> `api_key: "sk-abcdef..."`。它能跑通，所以没人会改——
> 直到某天它出现在 git 历史里，而且**历史是改不掉的**。

### 3.2 值的来源优先级

```
真实环境变量  >  .env  >  configs/*.yaml 里的字面值  >  maixrag/config.py 的默认值
```

两条细节值得知道：

- `.env` **默认不覆盖已有的环境变量**。所以 CI 里可以直接 `CHAT_API_KEY=...`
  而不改任何文件，`load_dotenv` 会尊重它。
- yaml 里写 `"${CHAT_MODEL}"` 是**引用**环境变量，不是字面值。
  变量没设时它会**保持原样**（而不是变成空串），
  这样报错信息里能直接看到"缺的是 `CHAT_MODEL`"，而不是面对一个空值猜。

### 3.3 需要配什么

只有两组，各自三个变量：

```bash
# ---- 对话模型：生成答案、LLM-as-judge ----
CHAT_BASE_URL=https://api.deepseek.com/v1
CHAT_MODEL=deepseek-flash
CHAT_API_KEY=sk-...

# ---- 嵌入模型：检索用 ----
EMBED_BASE_URL=http://127.0.0.1:11434/v1
EMBED_MODEL=bge-m3
EMBED_API_KEY=ollama
```

**为什么嵌入和对话要分开配**——因为它们是两种完全不同的负载：

| | 对话模型 | 嵌入模型 |
| --- | --- | --- |
| 调用频率 | 每轮 1 次 | 建索引时几千次 |
| 对延迟敏感 | 是（人在等） | 否（离线批量） |
| 对质量敏感 | 高 | **更高**——检索错了，后面全错 |
| 成本 | 按 token 计费 | 本地跑是 0 |

所以本项目的默认是"对话用云、嵌入用本地"。这不是省钱的权宜之计，
而是**嵌入是检索的地基，地基不该依赖一个每次都联网、会限流、会涨价的外部服务**。

> 实测：DeepSeek **不提供** `/embeddings` 接口（404），
> 所以"全用 DeepSeek"这条路根本走不通。这是 [事故档案](../postmortem/) 之外的
> 一个纯事实约束，写在这里免得你重复试一遍。

### 3.4 用本地模型（零密钥、零联网）

本项目的 `local` 预设让对话与嵌入都跑在本机 Ollama 上：

```bash
ollama pull bge-m3          # 嵌入，约 1.1 GB
ollama pull qwen2.5:7b      # 对话
python -m maixrag setup --preset local
```

**但必须说清一个限制**：本项目的 agent 用 **JSON 协议**跟模型对话
（它要从回复里解析出"调哪个工具"），而 7B 级别的本地模型经常做不到，
表现为反复返回无法识别的决策。所以：

| 你要做的事 | 本地小模型够吗 |
| --- | --- |
| 看检索效果（`eval --fake-chat`） | ✅ 够 |
| 跑通全流程（`--fake-chat`） | ✅ 够 |
| 用 agent 做真实多跳问答 | ⚠️ 需要 14B+，或换更强的模型 |

向导会在自检里**专门测一次 JSON 模式**，不通就提醒你——
不测这一步的话，会出现"向导说一切正常，然后 agent 一条都跑不通"。

### 3.5 不看向导，直接改文件

这是完全等价的一条路，而且**更适合脚本化**：

```bash
# 复制示例，然后编辑
copy .env.example .env          # Windows
cp .env.example .env            # Linux / macOS
```

或者用命令行直接给值（不提问、不交互）：

```bash
python -m maixrag setup ^
  --chat-base-url https://api.deepseek.com/v1 ^
  --chat-model deepseek-flash ^
  --chat-key sk-xxxx ^
  --embed-base-url http://127.0.0.1:11434/v1 ^
  --embed-model bge-m3 ^
  --embed-key ollama
```

只想**看**当前配成了什么：

```bash
python -m maixrag setup --check           # 列出生效值，密钥打掩码
python -m maixrag setup --check --probe   # 并且真的连一次
```

## 4. 亲眼看一次

**向导正常跑完的样子：**

```
[1/4] 选一个组合
  1) DeepSeek 云端对话 + 本地 Ollama 嵌入
     本项目实测可用的组合。对话花钱、嵌入不花钱，语料可离线复现。
  2) 全本地（Ollama 跑对话 + 嵌入）
  3) 任意 OpenAI 兼容端点（自填）

[4/4] 连通性自检（真的发请求）
  · 嵌入端点 …
    ✓ 返回 1024 维向量
  · 对话端点 …
    ✓ 模型回了 'OK'
  · JSON 模式（agent 靠它做决策）…
    ✓ JSON 解析成功：{'status': 'ok'}

已写入 D:\...\.env
  · CHAT_BASE_URL = https://api.deepseek.com/v1 （更新）
  · CHAT_MODEL = deepseek-flash （更新）
  · CHAT_API_KEY = sk-0…1294（35 字符） （更新）
  · EMBED_MODEL = bge-m3 （更新）
  · 权限已收紧（仅 chuan 可访问）
```

**注意自检报告里那个"返回 1024 维向量"。** 维度值得专门报出来：
索引是按维度存的，换一个嵌入模型而维度不同，旧索引必须重建。
"换了模型却还在用旧索引"是这一章最容易踩、也最难查的坑（见 6.3）。

**体检的样子**（出问题时第一个该跑的命令）：

```bash
$ python -m maixrag setup --check
当前生效的配置（密钥只显示掩码）：
  · 对话 base_url      https://api.deepseek.com/v1
  · 对话 model         deepseek-flash
  · 对话 api_key       sk-0…1294（35 字符）
  · 嵌入 base_url      http://127.0.0.1:11434/v1
  · 嵌入 model         bge-m3
  · 嵌入 api_key       ******
  · 检索模式            retrieve
  · 检索器              dense + bm25
  · 融合                rrf
  · top_k              5
  · agent 轮次预算       12
  · agent 工具          search_docs, read_doc, lookup_api, list_api, check_api_usage

配置可用。
```

## 5. 证据

**密钥的六条安全约定**，每条都有对应的实现位置：

| 约定 | 实现 |
| --- | --- |
| 密钥只进 `.env` | `setup.py` 的 `EnvFile` 只写 `ENV_KEYS` 白名单里的键 |
| `.env` 必须被 git 忽略 | 写盘前调 `git check-ignore`，**不是忽略就中止** |
| 文件权限只给当前用户 | POSIX `chmod 600`；Windows `icacls /inheritance:r` |
| 永不回显明文 | 所有打印走 `mask()`：`sk-0…1294（35 字符）` |
| 不进报告与日志 | `Config.to_dict()` 把 `api_key` 替换成 `<redacted>` |
| 不进 `configs/` | 向导只写 `.env`，没有写 yaml 的代码路径 |

**回归测试**（`tests/test_setup.py`，15 条）锁住的是其中最危险的几条：

| 断言 | 为什么重要 |
| --- | --- |
| `test_wizard_aborts_when_env_is_not_gitignored` | **配好密钥却提交上去，比配不好糟糕得多** |
| `test_wizard_output_shows_masked_key_only` | 漏一处掩码，密钥就进了终端回滚缓冲与截图 |
| `test_wizard_writes_nothing_when_probe_fails` | 半截的 `.env` 会让下次查错方向 |
| `test_envfile_preserves_comments` | 就地改，不冲掉解释"为什么这么配"的注释 |
| `test_wizard_keeps_existing_key_when_user_presses_enter` | 否则重跑一次向导就把密钥清空了 |
| `test_local_preset_needs_no_key_anywhere` | "全本地"必须真的零密钥，这是它存在的全部意义 |

**自检走的是真实调用路径**，不是另写一个轻量探针：
`probe_chat` 用的是 `OpenAICompatChat`、`probe_embed` 用的是 `OpenAICompatEmbedder`。
理由是**探针能通而真实路径不通，是最典型的假安全感**。

## 6. 失败的样子

### 失败一：密钥进了 git 历史

```bash
$ git log --all -S "sk-" --oneline
a1b2c3d  把密钥填进 configs/l2_hybrid.yaml，方便演示
```

这一条**没有便宜的修法**。改写历史要 force push，而如果已经推送过、
别人已经拉过，你就得假设它已经泄露，去吊销重发。

所以本项目的做法是**不让它发生**：向导在写盘前先问
`git check-ignore .env`，不是忽略就拒绝写入并告诉你怎么办。

### 失败二：配了，但报"未配置 API Key"

最可能的原因不是密钥写错，是**代码路径没走到那一步**。
本项目真出现过一次：走 `--config` 时 yaml 里的 `${VAR}` 会被展开，
而走默认配置（不传 `--config`）时**不展开**。
于是"未配置 API Key"只在**一半的用法**里出现，而 `.env` 里明明配着。

> 这类 bug 的通用形态：**校验没错、数据没错、报错信息也没错，
> 错的是"两条路只有一条做了该做的事"。**
> 修完之后加了 `scripts/check_default_config_expands.py` 锁住它。

诊断第一步永远是：

```bash
python -m maixrag setup --check
```

它告诉你**当前生效**的值。配置类问题里有一半是"我以为它是 A，其实它是 B"。

### 失败三：换了嵌入模型，没重建索引

症状很隐蔽：不报错，检索结果只是**变差**（甚至看起来"差不多"）。

因为索引里存的是**旧模型算出来的向量**，而你用新模型去编码查询——
两个向量不在同一个空间里，余弦相似度基本等于随机。

规矩很简单：

> **嵌入模型变了，索引就必须重建。**

```bash
python -m maixrag index build --rebuild
```

这也是向导要把"返回多少维"报出来的原因：维度变了你一眼就能看见。

### 失败四：向导说配好了，agent 还是不用工具

对话能通不代表模型肯按 JSON 回答。所以自检专门测一次 JSON 模式，
不通时会给出提醒而不是假装成功：

> 对话能用但不肯按 JSON 回答：检索与评测没问题，
> agent 循环可能不稳。换一个更强的模型，或加提示词约束。

**"能连通"和"能干活"是两件事**，自检要测的是后者。

## 7. 自检

```bash
python -m maixrag setup --check --probe          # 配置体检 + 真连一次
python -m maixrag setup --list-presets           # 看有哪几种组合
python -m pytest tests/test_setup.py -q          # 密钥安全约定的回归测试
git check-ignore -v .env                         # 确认 .env 真的被忽略
```

自检问题（不查代码回答）：

1. 为什么密钥可以放在 `configs/*.yaml` 里"跑得通"，却绝对不该放？
2. `.env` 里 `CHAT_MODEL=deepseek-flash`，同时 shell 里
   `export CHAT_MODEL=other`，最终生效的是哪个？为什么这样设计？
3. 换嵌入模型之后忘了重建索引，会报错吗？如果不会，你怎么发现它坏了？

## 8. 课后习题

**A1（复现）** 把 `.env` 里的 `EMBED_BASE_URL` 改成一个不存在的端口，
跑 `--check --probe`，记录它报什么；再跑一次 `demo --fake-chat`，看是否还能跑。

- 验收：能解释为什么"体检不过"和"演示能跑"可以同时成立
- 追问：这个组合会不会让人误判"配置没问题"？

**B1（诊断）** 同事说："我把密钥写进 `configs/local.yaml` 了，能跑，
你别管那么细。"列出至少两条具体的、可能发生的后果，
并说明**为什么"能跑"不构成放行的理由**。

- 验收：答案里要有"改不掉的 git 历史"这一类**不可逆**的代价
- 提示：设身处地想一下，如果你要接手这个仓库

**C1（改造）** 给 `setup.py` 加一个 `--from-dsh` 选项：
从 DSH 的凭证存储（`$DSH_HOME/.credentials.yaml` 的 `refs`）读密钥，
而不是让人手敲。

- 验收：仍然满足全部六条安全约定（尤其"不回显明文"）
- 参考：`scripts/sync_dsh_credentials.py` 已经做了一半
- 追问：自动读取别人的凭证文件，需不需要**先问一句**？为什么？

**D1（判断）** 向导是"降低门槛"还是"掩盖问题"？
有人认为"配置文件就该让用户自己看、自己改，向导是多此一举"。

- 验收：你的答案要同时说清向导的**收益**和它的**代价**，
  以及本项目用什么办法压住那个代价（提示：3.5 和 `--check`）
- 参考：[design 07 文档体系设计](../design/07-文档体系设计.md) 里
  "不藏起来"的那条原则
